---
title: Heavy Swarm
description: Multi-phase orchestration that decomposes a task into specialized questions, runs them through expert agents in parallel, and synthesizes a final answer
---

The `HeavySwarm` is a multi-agent orchestration system inspired by X.AI's Grok Heavy implementation. It decomposes a task into role-specific questions, runs those questions through specialized expert agents in parallel, and then synthesizes the outputs into a single comprehensive answer. The exact set of experts is controlled by the `variant` parameter.

## When to Use

- **Complex research tasks** — in-depth investigation across multiple angles
- **Financial analysis** — investment decisions requiring multiple viewpoints
- **Strategic planning** — comprehensive evaluation of options and trade-offs
- **Due diligence** — thorough verification and risk assessment
- **Multi-faceted problems** — issues that need research, analysis, and synthesis combined

## Key Features

- Intelligent question generation tailored to each agent role, with its own decomposer per variant
- Image-aware decomposition: pass `img` and the questions are written from what the image shows
- Three preset variants — `default` (5 agents), `medium` (4 Grok-style agents), `heavy` (16 agents)
- Parallel execution on a thread pool; each worker runs the [autonomous loop](/agents/autonomous-mode) on its question
- Synthesis agent that integrates expert outputs into a final answer
- Token usage summed across question generation and every agent, via `usage`
- Optional real-time `rich` dashboard
- Multi-loop iterative refinement (each loop builds on the previous result)
- Tool integration through `worker_tools`
- Inherits `SerializableMixin` — `to_dict()` is available for telemetry / persistence

## Architecture

```
1. Question Generation
   - The question model (question_agent_model_name) reads the task,
     and the image when one is given
   - Calls a function with one question per expert role

2. Parallel Expert Execution (variant-dependent)
   - default : Research, Analysis, Alternatives, Verification
   - medium  : Harper, Benjamin, Lucas
   - heavy   : 15 domain specialists

3. Synthesis
   - default: Synthesis-Agent; medium: Captain-Swarm; heavy: Grok
   - Receives the conversation as chat turns: task, questions, every answer
   - Produces the final report

4. Optional Multi-Loop Refinement
   - Each subsequent loop receives the previous synthesis as context
```

## Basic Example

```python
from swarms import HeavySwarm

swarm = HeavySwarm(
    name="Investment-Research-Team",
    description="Comprehensive investment analysis",
    question_agent_model_name="gpt-5.4",
    worker_model_name="gpt-5.4",
    show_dashboard=True,
    max_loops=1,
)

result = swarm.run(
    "Should we invest in NVIDIA stock? Provide detailed analysis."
)
print(result)
```

## With Tool Integration

```python
from swarms import HeavySwarm
from swarms_tools import exa_search

swarm = HeavySwarm(
    name="Market-Research-Team",
    description="Research team with web search capabilities",
    question_agent_model_name="gpt-5.4",
    worker_model_name="claude-sonnet-4-6",
    worker_tools=[exa_search],   # tools available to every worker
    show_dashboard=True,
    max_loops=2,                 # iterative refinement
)

result = swarm.run(
    "Find the best 3 gold ETFs with current data from the web"
)
```

## Selecting a Variant

The `variant` parameter controls which agents are instantiated.

```python
# Five-agent default (Research / Analysis / Alternatives / Verification + Synthesis)
swarm = HeavySwarm(variant="default")

# Four-agent Grok-style team (Captain + Harper, Benjamin, Lucas)
swarm = HeavySwarm(variant="medium")

# Sixteen-agent deep team (Grok captain + 15 domain specialists)
swarm = HeavySwarm(variant="heavy")
```

`SwarmVariant` is exported from `swarms.agents.heavy_swarm_agents`. Passing an unknown variant raises `ValueError` during initialization.

## Methods

### `run(task, img=None)`

Execute the full multi-phase workflow.

```python
result = swarm.run(
    task="Analyze cryptocurrency market trends",
    img=None,   # optional image input
)
```

Each call clears the swarm's conversation first, so the returned transcript covers only the current task.

### `usage`

Provider token counts summed over question generation and every agent, including the synthesis agent or captain. The total keeps growing across loops and `run()` calls. See [Token usage](/agents/token-usage).

```python
swarm.run("Analyze cryptocurrency market trends")
print(swarm.usage)
# {"input_tokens": ..., "output_tokens": ..., "cached_tokens": ...,
#  "reasoning_tokens": ..., "total_tokens": ...}
```

### `get_questions_only(task, img=None)` and `get_questions_as_list(task, img=None)`

Run only the decomposer and return its questions as a dict of `*_question` keys or as an ordered list. Useful for previewing what each worker will be asked.

```python
questions = swarm.get_questions_only("Analyze market trends for EVs")
```

### `to_dict()`

Inherited from `SerializableMixin`. Returns a JSON-friendly snapshot of the swarm's config. The `agents`, `conversation`, `dashboard`, and `worker_tools` attributes are excluded via `_to_dict_exclude` to keep the snapshot lightweight.

```python
snapshot = swarm.to_dict()
```

## Question Generation

The question agent emits a JSON object whose schema depends on the variant. For the default variant it looks like:

```python
{
    "thinking": "Reasoning for how to break down the task",
    "research_question": "Question for Research Agent",
    "analysis_question": "Question for Analysis Agent",
    "alternatives_question": "Question for Alternatives Agent",
    "verification_question": "Question for Verification Agent"
}
```

The `"medium"` and `"heavy"` variants return one `<name>_question` key per specialist instead, such as `harper_question`. Each variant has its own decomposer prompt and schema, and the decomposer sends no temperature or top-p, so it also runs on Anthropic models. When you pass `img`, the decomposer is told an image accompanies the task and reads it.

Example generated questions for *"Invest in NVIDIA?"*:

```json
{
    "thinking": "Need to evaluate financials, market position, alternatives, and risks",
    "research_question": "Research NVIDIA's financial performance, product pipeline, and market position in AI chips",
    "analysis_question": "Analyze NVIDIA's revenue growth, profit margins, and competitive advantages in the AI accelerator market",
    "alternatives_question": "What are alternative semiconductor investments with similar growth potential?",
    "verification_question": "Verify NVIDIA's claimed AI leadership and assess risks to their market dominance"
}
```

## Multi-Loop Refinement

With `max_loops > 1` the swarm iterates, each loop feeding the previous synthesis back as context:

```python
swarm = HeavySwarm(
    name="Deep-Analysis-Team",
    worker_model_name="claude-sonnet-4-6",
    max_loops=3,
)

result = swarm.run("Complex strategic decision")
```

Per-loop semantics:

1. Loop 1: original task only
2. Loop 2: `"Previous loop results: <output>\n\nOriginal task: <task>\n\n"` followed by an instruction to refine and build on the previous loop
3. Loop 3: same shape — refine, fill gaps, deepen the analysis

The conversation is kept across loops within one `run()`, so a later synthesis also sees the earlier loops' questions and answers.

## Performance Notes

### Parallel Execution

All workers fan out on a thread pool that carries the tracing context into each thread. `self.max_workers` is set to `int(os.cpu_count() * 0.9)`; it is not a constructor parameter.

```python
with ContextThreadPoolExecutor(max_workers=self.max_workers) as executor:
    future_to_agent = {
        executor.submit(execute_agent, task): task[0]
        for task in agent_tasks
    }
```

### Timeout

```python
swarm = HeavySwarm(timeout=900)
```

The timeout is passed to `future.result()` after `as_completed()` has already returned that future, so it does not cut a slow worker short.

### Verbose Logging

```python
swarm = HeavySwarm(
    verbose=True,
    agent_prints_on=True,
)
```

## Output Structure

The swarm returns the conversation history formatted by `output_type`. The default `"dict-all-except-first"` returns a list of message dicts, without the initial task message:

```python
[
    {"role": "Question Generator Agent", "content": {...}},
    {"role": "Research-Agent", "content": "<research findings>"},
    {"role": "Analysis-Agent", "content": "<analysis insights>"},
    {"role": "Alternatives-Agent", "content": "<alternative options>"},
    {"role": "Verification-Agent", "content": "<verification results>"},
    {"role": "Synthesis Agent", "content": "<comprehensive synthesis>"},
]
```

Worker messages appear in the order the workers finished. Each message also carries `timestamp`, `message_id` and `category` keys. Use `output_type="final"` to get only the synthesis.

## Best Practices

<Note>
  **Model Selection:** use stronger models (Claude Sonnet, GPT-5.4) for worker agents on complex tasks.
</Note>

1. **Question Quality** — a stronger question-generation model produces tighter, less overlapping expert questions.
2. **Worker Models** — balance cost vs quality for the worker pool; mixing providers via RouteHub works out of the box.
3. **Loop Count** — start at `max_loops=1`. Add more only when the synthesis clearly needs refinement.
4. **Variant Choice** — `default` covers most tasks; reach for `heavy` only when you genuinely benefit from 15+ specialist perspectives.
5. **Dashboard** — leave on for demos and debugging; off for production.
6. **Tools** — supply `worker_tools` when the task requires real-time data (search, web fetch, etc.).

<Warning>
  HeavySwarm is resource-intensive. Each loop runs N expert agents + a question generator + a synthesizer. Token costs scale roughly linearly with both `variant` and `max_loops`.
</Warning>

## Reliability Checks

`reliability_check()` runs automatically during `__init__`:

```python
# Validation: worker_model_name and question_agent_model_name must be set

try:
    swarm = HeavySwarm(worker_model_name=None)
except ValueError as e:
    print(e)
```

When `show_dashboard=True`, the validation steps animate through the dashboard. Otherwise a single confirmation panel prints.

An unknown `variant` raises `ValueError` before this check, when `__init__` builds the agents.

## Error Handling

`run()` does not raise when a phase fails. It logs the error and returns a message string instead of the formatted conversation:

```python
result = swarm.run("Task")

if isinstance(result, str) and result.startswith(
    ("Error", "Failed", "Critical error")
):
    print(f"Swarm execution failed: {result}")
```

If a single worker raises, the error is logged, that worker's answer is left out of the conversation, and the other workers and the synthesis still run.
