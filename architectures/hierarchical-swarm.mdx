---
title: Hierarchical Swarm
description: Director-worker pattern where a central director plans, delegates, and (optionally) judges or refines specialist agents through feedback loops
---

The `HierarchicalSwarm` implements a director-worker pattern. A central director agent analyzes the task, returns structured orders (an `OrderBatch`) for specialist worker agents, and — optionally — provides feedback or runs a judge over the outputs to iterate further.

## When to Use

- **Complex project management** — multi-stage projects with specialized roles
- **Team coordination** — coordinating diverse specialist agents
- **Quality control** — iterative refinement through feedback loops
- **Hierarchical decisions** — tasks requiring oversight and delegation
- **Strategic planning** — breaking down complex goals into specialized subtasks

## Key Features

- Automatic director agent creation (or pass your own)
- Structured orders via `OrderBatch` (Pydantic schema of `agent_name` + `task` pairs)
- A console panel of the director's orders, and its plan when it returns one, at every step
- Multi-loop feedback and refinement
- Optional agent-as-judge phase for objective scoring
- Optional planning phase before order generation
- Optional team-awareness preamble for workers
- Parallel order execution (default)
- Worker retries, and director reassignment of failed tasks
- Conversation history tracking, reset at the start of every run
- Autosave of conversation history to a workspace directory

## Basic Example

```python
from swarms import Agent, HierarchicalSwarm

content_strategist = Agent(
    agent_name="Content-Strategist",
    system_prompt="Develop content strategies and editorial calendars.",
    model_name="gpt-5.4",
)

creative_director = Agent(
    agent_name="Creative-Director",
    system_prompt="Create compelling advertising concepts and visual direction.",
    model_name="gpt-5.4",
)

seo_specialist = Agent(
    agent_name="SEO-Specialist",
    system_prompt="Conduct keyword research and optimize content for search.",
    model_name="gpt-5.4",
)

swarm = HierarchicalSwarm(
    name="Marketing-Team",
    description="Comprehensive marketing team for product launches",
    agents=[content_strategist, creative_director, seo_specialist],
    max_loops=2,            # the second loop builds on the first
)

result = swarm.run(
    "Develop a marketing strategy for a new SaaS project management tool"
)
print(result)
```

## Architecture Flow

```
1. User task → Director Agent
2. (Optional) A planning pass writes a text plan into the conversation
3. Director emits an OrderBatch:
   - orders: list of (agent_name, task) pairs
4. The orders panel prints (print_on=True)
5. Orders execute (parallel by default); failed workers are retried,
   then reassigned by the director
6. Worker outputs are added to the shared conversation
7. (Optional) Judge agent scores outputs, OR director feedback
8. Loop back to step 2 with the previous result until max_loops,
   then return the conversation formatted by output_type
```

## Order structure

The default director returns its orders through a function call that matches `OrderBatch`. The schemas live in `swarms.schemas.hs_schemas`:

```python
from typing import List

from pydantic import BaseModel

class HierarchicalOrder(BaseModel):
    agent_name: str   # worker agent that should execute
    task: str         # specific task for that agent

class OrderBatch(BaseModel):
    orders: List[HierarchicalOrder]

class SwarmSpec(BaseModel):
    plan: str
    orders: List[HierarchicalOrder]
```

Example output:

```json
{
    "orders": [
        {"agent_name": "Content-Strategist", "task": "Develop 90-day content calendar"},
        {"agent_name": "Creative-Director", "task": "Create brand visual identity"},
        {"agent_name": "SEO-Specialist", "task": "Research keywords for SaaS project management"}
    ]
}
```

`SwarmSpec` is the older shape with a `plan`. A custom director can still return it, and the plan then appears above the orders in the console panel. `parse_orders()` accepts either shape, as a model, JSON string, dict or tool call.

## Key Parameters

<ParamField path="name" type="str" default="HierarchicalAgentSwarm">
  Name for the swarm instance.
</ParamField>

<ParamField path="description" type="str" default="Distributed task swarm">
  Description of the swarm's purpose.
</ParamField>

<ParamField path="agents" type="List[Agent]" required>
  Specialist worker agents.
</ParamField>

<ParamField path="director" type="Agent">
  Custom director agent. If `None`, a default director is created using `director_model_name` + `director_system_prompt`. A custom director must return orders; see [Custom director](#custom-director).
</ParamField>

<ParamField path="max_loops" type="int" default="1">
  Maximum number of plan → execute → feedback iterations.
</ParamField>

<ParamField path="output_type" type="OutputType" default="dict-all-except-first">
  Format of the returned conversation history.
</ParamField>

<ParamField path="director_name" type="str" default="Director">
  Display name for the director agent.
</ParamField>

<ParamField path="director_model_name" type="str" default="gpt-5.4">
  Model used by the director.
</ParamField>

<ParamField path="director_system_prompt" type="str" default="HIEARCHICAL_SWARM_SYSTEM_PROMPT">
  System prompt for the director. Override to customize director behavior.
</ParamField>

<ParamField path="director_temperature" type="float" default="0.7">
  Sampling temperature for the director.
</ParamField>

<ParamField path="director_top_p" type="float" default="0.9">
  Top-p for the director.
</ParamField>

<ParamField path="feedback_director_model_name" type="str" default="gpt-5.4">
  Model for the separate agent that writes feedback on worker outputs.
</ParamField>

<ParamField path="director_feedback_on" type="bool" default="False">
  Enable director feedback after each loop except the last. Has no effect when `max_loops=1` or `agent_as_judge=True`.
</ParamField>

<ParamField path="planning_enabled" type="bool" default="False">
  Run an explicit planning pass before generating orders.
</ParamField>

<ParamField path="agent_as_judge" type="bool" default="False">
  Run a judge agent that scores worker outputs after each step. Replaces director feedback.
</ParamField>

<ParamField path="judge_agent_model_name" type="str" default="gpt-5.4">
  Model used by the judge agent when `agent_as_judge=True`.
</ParamField>

<ParamField path="director_settings" type="Optional[Dict[str, Any]]" default="None">
  Additional `Agent` constructor settings for the automatically created director. These values override the legacy director parameters. Set `planning_system_prompt` in this dictionary to customize the optional planning pass.
</ParamField>

<ParamField path="max_agent_retries" type="int" default="1">
  Number of retries after a worker's initial execution fails. When retries are exhausted, the worker is marked unavailable in the shared swarm conversation.
</ParamField>

<ParamField path="max_reassignment_attempts" type="int" default="1">
  Maximum number of recovery rounds in which the director can move failed tasks to healthy workers. A failed task does not stop successful workers or abort the swarm.
</ParamField>

<ParamField path="add_collaboration_prompt" type="bool" default="True">
  Forwarded to the roster helper that seeds the shared conversation. The roster is added to the conversation before the collaboration prompt would be appended, so this flag currently has no effect.
</ParamField>

<ParamField path="multi_agent_prompt_improvements" type="bool" default="False">
  Augment every worker's system prompt with team awareness (other agents + roles).
</ParamField>

<ParamField path="parallel_execution" type="bool" default="True">
  Execute multi-agent orders concurrently within a loop.
</ParamField>

<ParamField path="max_workers" type="int" default="None">
  The most orders that run at once when `parallel_execution` is `True`. When unset, every order in a loop runs at once. Must be greater than zero if provided.
</ParamField>

<ParamField path="interactive" type="bool" default="False">
  Prompt for a task on the console when `run()` is called without one. Also turns off every worker's `print_on`.
</ParamField>

<ParamField path="print_on" type="bool" default="True">
  Print the director's orders, and its plan when it returns one, in a panel at every step.
</ParamField>

<ParamField path="autosave" type="bool" default="False">
  Persist conversation history to a workspace directory.
</ParamField>

<ParamField path="verbose" type="bool" default="False">
  Log the autosave directory and each save.
</ParamField>

<ParamField path="channel" type="CommsChannel" default="None">
  A comms channel the swarm posts to: the task, the director's plan and orders, each worker's report and the director's feedback. Each run's conversation is seeded with what the channel already holds. See [Comms Channels](/api/channels/overview).
</ParamField>

<Note>
  The swarm enforces `output_type="final"` on all configurable director and worker agents so only final responses pass between agents. The swarm-level `output_type` still determines the value returned from `run()`.
</Note>

## Methods

### `run(task, img=None)`

Execute the swarm end-to-end.

```python
result = swarm.run(
    task="Develop product launch strategy",
    img=None,
)
```

### `batched_run(tasks, ...)`

Run the swarm sequentially over a batch of tasks. Each task starts from an empty conversation and fresh delivery cursors, so one task's messages never leak into the next.

```python
results = swarm.batched_run([
    "Strategy for product A",
    "Strategy for product B",
    "Strategy for product C",
])
```

### `display_hierarchy()`

Visualize the swarm's tree with `rich.Tree`.

```python
swarm.display_hierarchy()
# Panel "HierarchicalSwarm Hierarchy: Marketing-Team"
# 🎯 Director [gpt-5.4]
# ├── 🤖 Content-Strategist [gpt-5.4] - <description>
# ├── 🤖 Creative-Director [gpt-5.4] - <description>
# └── 🤖 SEO-Specialist [gpt-5.4] - <description>
```

### `feedback_director(outputs)`

Manually trigger the feedback director on a list of worker outputs. It reviews the latest worker messages in the conversation and records its feedback under the director's name.

### `run_judge_agent(outputs)`

Manually score the conversation with the judge agent. It works whether or not `agent_as_judge` is set; the flag only decides whether `step()` calls it. `outputs` is returned as a string if the judge fails.

### `parse_orders(output)`

Extract `(plan, orders)` from a director response. `plan` is `None` for an `OrderBatch`. Raises `ValueError` when the output carries no orders.

## Advanced Configuration

### Custom director

To change the auto-created director's name, model or prompt, use `director_settings`. It keeps the `OrderBatch` function schema the swarm needs:

```python
swarm = HierarchicalSwarm(
    name="Executive-Team",
    agents=workers,
    director_settings={
        "agent_name": "Chief-Strategy-Officer",
        "model_name": "claude-sonnet-4-6",
        "top_p": None,
    },
)
```

<Note>
  The auto-created director sends both `director_temperature` (0.7) and `director_top_p` (0.9). Anthropic's current models reject the two together, so set one to `None` for a Claude director, as above.
</Note>

A director you pass yourself must return orders that `parse_orders()` can read: an `OrderBatch` or `SwarmSpec`, JSON or a dict with an `orders` key, or a tool call carrying one. A plain-text director fails every loop, and `run()` then raises. This director returns a `SwarmSpec`, so its plan shows in the panel:

```python
from swarms import HierarchicalSwarm, LiteLLM
from swarms.schemas.hs_schemas import SwarmSpec

director = LiteLLM(
    model_name="gpt-5.4",
    response_format=SwarmSpec,
    system_prompt="Plan the work, then assign one clear task to each relevant agent.",
)

swarm = HierarchicalSwarm(
    name="Executive-Team",
    agents=workers,
    director=director,
)
```

### Planning + Multiple Loops

```python
swarm = HierarchicalSwarm(
    name="Research-Team",
    agents=researchers,
    planning_enabled=True,
    max_loops=3,
)
```

With `planning_enabled=True`:

1. A planning agent, using `DIRECTOR_PLANNING_PROMPT` or `director_settings["planning_system_prompt"]`, writes a text plan without orders
2. The plan is added to the conversation under the director's name
3. Director then emits concrete orders
4. Workers whose `run()` accepts `messages` see the plan in their message history

<Note>
  The director's history excludes messages recorded under its own name, so the plan reaches the workers but not the order-writing director.
</Note>

### Agent-as-Judge

```python
swarm = HierarchicalSwarm(
    name="Reviewed-Team",
    agents=workers,
    agent_as_judge=True,
    judge_agent_model_name="claude-sonnet-4-6",
    max_loops=2,
)
```

When enabled, after worker outputs are gathered the judge agent reads the conversation and returns a structured `JudgeReport`: an overall 0-10 score, an `AgentScore` per worker and a summary. The report is added to the conversation and passed to the next loop as the previous result. Director feedback is skipped while the judge is on.

### Team-Awareness Preamble

```python
swarm = HierarchicalSwarm(
    agents=workers,
    multi_agent_prompt_improvements=True,
)
```

Each worker's `system_prompt` is extended with a description of every other team member so workers can write coherent hand-offs.

### Orders panel and interactive mode

With the default `print_on=True`, every step prints a panel titled with the director's name. It lists each order in full as `agent - task`, under the director's plan when the director returns one. Set `print_on=False` to hide it.

```python
swarm = HierarchicalSwarm(
    name="Development-Team",
    agents=developers,
    interactive=True,
)

# Prompts for the task on the console because none is passed
result = swarm.run()
```

`interactive=True` does not open a dashboard. It reads the task from the console when `run()` gets none, and silences the workers' own printing.

### Autosave

```python
swarm = HierarchicalSwarm(
    agents=workers,
    autosave=True,
)
```

When enabled, the swarm writes `conversation_history.json` under
`$WORKSPACE_DIR/swarms/HierarchicalSwarm/{name}-{timestamp}/`.
If `WORKSPACE_DIR` is unset it defaults to `./agent_workspace`. The directory is created once, at construction, and the file is rewritten at the end of every run.

## Multi-Loop Refinement

With `max_loops > 1`, the director can refine outputs across iterations:

```python
swarm = HierarchicalSwarm(
    agents=workers,
    max_loops=3,
    director_feedback_on=True,
)
```

Each loop:

1. From the second loop on, the director's task is the previous loop's result plus the original task
2. Director issues orders (possibly to different agents or with different tasks)
3. Workers execute
4. Results — and any feedback/judge output — are appended to the conversation, followed by a `--- Loop N/M completed ---` marker
5. The next loop's director receives the messages it has not seen yet

A loop that raises is marked `--- Loop N/M failed: <error> ---`, and the next loop still runs.

## Order Execution

### Concurrent Execution (default)

Orders for multiple agents run in parallel on a thread pool sized by `max_workers` (`execute_orders`). Outputs are added to the conversation in order sequence once every order has finished:

```python
orders = [
    {"agent_name": "Agent1", "task": "Analyze data"},
    {"agent_name": "Agent2", "task": "Research market"},
    {"agent_name": "Agent3", "task": "Review competitors"},
]
# All three execute simultaneously when parallel_execution=True
```

### Sequential Execution

Set `parallel_execution=False` to run orders one after another within a loop. Each output is added to the conversation as soon as it finishes, so later workers see earlier ones. Useful when each order depends on the previous one's output.

## Director System Prompt

The default `HIEARCHICAL_SWARM_SYSTEM_PROMPT`, in `swarms.prompts.hierarchical_swarm_prompts`, instructs the director to:

- Review the swarm's goals
- Decompose the task into granular subtasks
- Match each subtask to the best-suited agent
- Write one clear `HierarchicalOrder` per task
- Return only an `OrderBatch`, with no plan or other top-level fields

You can fully override it. The auto-created director keeps the `OrderBatch` function schema whatever the prompt says:

```python
custom_prompt = """
You are a senior project director coordinating a team of specialists.

Responsibilities:
1. Analyze complex tasks and break them down.
2. Assign work to appropriate specialists.
3. Ensure team coordination and communication.
4. Review outputs and provide feedback.
5. Synthesize results into cohesive outcomes.

Always consider dependencies and optimal sequencing.
"""

swarm = HierarchicalSwarm(
    agents=workers,
    director_system_prompt=custom_prompt,
)
```

## Best Practices

<Note>
  **Loop count:** start at 1 loop for simple coordination; 2–3 for quality refinement. Avoid >3 unless you're seeing clear improvement per loop.
</Note>

1. **Specialized workers** — each agent should have an obviously different area of expertise; overlapping workers waste tokens.
2. **Director model** — use a stronger model than the workers (e.g. Claude Sonnet, GPT-5.4). The director's planning quality bounds the whole swarm.
3. **Loop balance** — every extra loop costs an additional director pass + every worker run. Budget accordingly.
4. **Planning phase** — enable for complex tasks that benefit from a strategy step.
5. **Judge phase** — enable when output quality is uneven and you want explicit scoring/feedback.
6. **Orders panel** — keep `print_on=True` while developing to see every delegation; turn it off when the console output is noise.

<Warning>
  Each loop runs the director **and** every selected worker. Costs grow roughly linearly with `max_loops × len(agents)`.
</Warning>

## Error Handling

Configuration errors raise `ValueError` when you construct the swarm, not when you run it:

```python
try:
    swarm = HierarchicalSwarm(agents=[], max_loops=1)
except ValueError as e:
    print(f"Configuration error: {e}")
```

`reliability_checks()` runs at construction and validates:

- At least one agent is provided
- `max_loops > 0`
- `max_agent_retries >= 0` and `max_reassignment_attempts >= 0`
- `max_workers > 0`
- Director agent can be created or is already valid

At run time, a failing worker is retried, then marked unavailable and reassigned; the swarm records it in the conversation and keeps going. A failing loop is recorded and the next loop runs. `run()` raises only when every loop fails:

```python
try:
    result = swarm.run("Task")
except Exception as e:
    print(f"Every loop failed: {e}")
```

## Performance Considerations

### Parallel Order Execution

`execute_orders` runs all orders for a loop simultaneously when `parallel_execution=True`. Each order gets its own thread, up to `max_workers` when set, and runs with its own retries.

### Conversation context

Each agent gets only what it needs from the shared conversation:

- **Director** — `"History: {new messages} \n\n Task: {task}"`, where the history holds only the messages it has not been given yet, tracked by a per-agent delivery cursor. The first call includes the worker roster.
- **Workers** — their order as the task, plus the conversation as typed chat turns when their `run()` accepts `messages`. The roster is left out.
- **Judge** — the conversation as typed chat turns.
- **Feedback director** — the current step's worker responses only.

`run()` starts a new conversation and resets the cursors, so every task starts clean. When the swarm has a `channel`, the new conversation is seeded with what the channel already holds, so a run can continue an earlier discussion.
