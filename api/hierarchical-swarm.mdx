## Overview

The `HierarchicalSwarm` class implements a hierarchical architecture where a director agent distributes tasks to worker agents as structured orders. The director can provide feedback and iterate on results through multiple loops to achieve desired outcomes while maintaining conversation history throughout the process.

Each step prints a panel with the director's orders, and its plan when the director returns one. Set `print_on=False` to hide it.

</ParamField>

<ParamField path="max_workers" type="int" default="None">

</ParamField>

<ParamField path="agent_as_judge" type="bool" default="False">
  When `True`, a judge agent scores the worker outputs after each step and returns a `JudgeReport`. It replaces director feedback, and its report becomes the previous-loop result the next loop builds on.
</ParamField>

<ParamField path="judge_agent_model_name" type="str" default="gpt-5.4">
  Model used by the judge agent when `agent_as_judge=True`.
</ParamField>

<ParamField path="director_settings" type="Optional[Dict[str, Any]]" default="None">
  Additional `Agent` constructor settings for the automatically created director. Values in this dictionary override the legacy director parameters. Use `planning_system_prompt` to customize the optional planning pass. The swarm always forces the director's `output_type` to `"final"`.
</ParamField>

<ParamField path="max_agent_retries" type="int" default="1">
  Number of retry attempts after a worker's initial execution fails. After all attempts are exhausted, the worker is marked unavailable in the shared conversation and its failure is reported to the director. Must be greater than or equal to `0`.
</ParamField>

<ParamField path="max_reassignment_attempts" type="int" default="1">
  Maximum number of recovery rounds in which the director can reassign failed tasks to healthy workers. The swarm continues running when recovery cannot complete a task. Must be greater than or equal to `0`.
</ParamField>

<ParamField path="channel" type="CommsChannel" default="None">
  A shared channel, such as `FileChannel("runs/q3.md")`. The swarm seeds its conversation from the channel, then posts the task and every agent's answer to it under the speaker's name. Member agents' own `channel` settings are detached with a warning, so only the swarm posts. See [Comms Channel](/agents/comms-channel#multi-agent-structures).
</ParamField>

<ParamField path="print_on" type="bool" default="True">
  Whether to print the director's orders, and its plan when it returns one, to the console at each step. Orders are shown in full, and the panel is titled with the director's name. This is separate from `verbose`, which controls logging
</ParamField>

<Note>
  `HierarchicalSwarm` forces every configurable director and worker agent to use `output_type="final"`. The swarm-level `output_type` parameter still controls the format returned by `HierarchicalSwarm.run()`.
</Note>

## Methods

### `run()`

```python
def run(
    self,
    task: Optional[str] = None,
    img: Optional[str] = None,
    *args,
    **kwargs,
) -> Any
```

Executes the hierarchical swarm for the specified number of feedback loops.

**Parameters:**

<ParamField path="task" type="str" optional>
  The initial task to be processed by the swarm. If None and interactive mode is enabled, will prompt for input
</ParamField>

<ParamField path="img" type="str" optional>
  Optional image input for the agents
</ParamField>

**Returns:**

<ResponseField name="result" type="Any">
  The formatted conversation history as output, formatted according to output_type configuration
</ResponseField>

**Workflow:**
1. Clears the conversation and every agent's delivery cursor, then re-adds the worker roster and the task, so each call starts clean
2. Director distributes orders to agents (after an optional planning pass)
3. Agents execute tasks and report back to director
4. Failed workers are retried up to `max_agent_retries`
5. Exhausted workers are marked unavailable in shared context
6. Director reassigns failed tasks to healthy workers, up to `max_reassignment_attempts`
7. Director evaluates results and issues new orders if needed (up to `max_loops`). Each later loop gets the previous loop's result and the original task
8. Records a `--- Loop N/M completed ---` or `--- Loop N/M failed: <error> ---` marker after every loop
9. Returns final output formatted per swarm-level `output_type`, and saves the conversation when `autosave=True`

<Warning>
  A loop that raises, for example because the director is unreachable or its output cannot be parsed, is recorded as failed and the next loop still runs. If every loop fails, `run()` re-raises the last error instead of returning a transcript.
</Warning>

### `step()`

```python
def step(
    self,
    task: str,
    img: str = None,
    *args,
    is_final_loop: bool = False,
    **kwargs,
) -> Any
```

Executes a single step of the hierarchical swarm workflow.

**Parameters:**

<ParamField path="task" type="str" required>
  The task to be processed in this step
</ParamField>

<ParamField path="img" type="str" optional>
  Optional image input for the task
</ParamField>

<ParamField path="is_final_loop" type="bool" default="False">
  Skips director feedback, which could not inform another loop
</ParamField>

**Returns:**

<ResponseField name="feedback" type="Any">
  The results from this step: the judge report when `agent_as_judge=True`, director feedback when it runs, otherwise the list of worker outputs. An empty list when the director issued no orders
</ResponseField>

**Process:**
1. Director runs (after the planning pass, if enabled) and returns orders
2. `parse_orders()` extracts the plan and orders; the panel prints them when `print_on=True`
3. Agents execute assigned tasks
4. Optional judge scoring or director feedback on results

Errors are not swallowed. If the director fails or its output cannot be parsed, `step()` raises and `run()` records the loop as failed.

### `parse_orders()`

```python
def parse_orders(self, output)
```

Parses a director response and returns a `(plan, orders)` tuple, where `orders` is a list of `HierarchicalOrder`. Accepts an `OrderBatch`, a `SwarmSpec`, a JSON string (decoded twice if double-encoded), a dict, an OpenAI-style tool call, or a list of tool calls or conversation turns. `plan` is `None` unless the output carries one. Raises `ValueError` when no `orders` can be found. The logic lives in `swarms/structs/hierarchical_order_parser.py`.

### `batched_run()`

```python
def batched_run(
    self,
    tasks: List[str],
    *args,
    img: Optional[Union[str, List[Optional[str]]]] = None,
    imgs: Optional[List[Optional[str]]] = None,
    max_workers: Optional[int] = None,
    return_agent_output_dict: bool = False,
    return_exceptions: bool = False,
    **kwargs,
)
```

Executes the hierarchical swarm for multiple tasks, calling `run()` once per task via the shared batch utility.

**Parameters:**

<ParamField path="tasks" type="List[str]" required>
  Tasks to execute
</ParamField>

<ParamField path="img" type="Optional[Union[str, List[Optional[str]]]]" optional>
  One image applied to every task, or one image per task
</ParamField>

<ParamField path="imgs" type="Optional[List[Optional[str]]]" optional>
  Images paired with tasks
</ParamField>

<ParamField path="max_workers" type="Optional[int]" default="None">
  Concurrent task limit; `None` runs tasks sequentially
</ParamField>

<ParamField path="return_agent_output_dict" type="bool" default="False">
  Return results keyed by task instead of as a list
</ParamField>

<ParamField path="return_exceptions" type="bool" default="False">
  Return exceptions instead of raising them
</ParamField>

**Returns:**

<ResponseField name="result" type="list | dict">
  Results in task order, or keyed by task when `return_agent_output_dict=True`
</ResponseField>

Each task starts from a clean conversation and delivery cursor, because `run()` resets both.

<Warning>
  All tasks share this one instance. With `max_workers` set, concurrent tasks clear and write the same conversation. Keep the default sequential mode unless you use one swarm per task.
</Warning>

### `reliability_checks()`

```python
def reliability_checks(self) -> None
```

Performs validation checks to ensure the swarm is properly configured.

**Validates:**
- At least one agent is provided
- max_loops is greater than 0
- max_agent_retries is greater than or equal to 0
- max_reassignment_attempts is greater than or equal to 0
- max_workers is greater than 0 when provided
- Director is available (creates default if needed)

**Raises:**
- `ValueError`: If swarm configuration is invalid

## Data Models

The schemas live in `swarms.schemas.hs_schemas`. `SwarmSpec` is also importable from `swarms.structs.hiearchical_swarm`.

### HierarchicalOrder

```python
class HierarchicalOrder(BaseModel):
    agent_name: str  # Name of agent assigned to execute task
    task: str        # Specific task to be executed
```

### OrderBatch

The schema the default director returns.

```python
class OrderBatch(BaseModel):
    orders: List[HierarchicalOrder]
```

### SwarmSpec

The legacy schema with a plan. A custom director can still return it; the plan is then shown in the orders panel.

```python
class SwarmSpec(BaseModel):
    plan: str                           # Director's overall plan
    orders: List[HierarchicalOrder]     # Task assignments to agents
```

### JudgeReport

Used when `agent_as_judge=True`. A one-shot judge agent scores each worker agent's output instead of the director issuing free-form feedback.

```python
class AgentScore(BaseModel):
    agent_name: str
    score: int          # 0-10
    reasoning: str
    suggestions: str

class JudgeReport(BaseModel):
    overall_quality: int    # 0-10
    scores: List[AgentScore]
    summary: str
```

## Usage Example

```python
from swarms import Agent, HierarchicalSwarm

# Create worker agents
research_agent = Agent(
    agent_name="Research-Specialist",
    system_prompt="Expert in research and data gathering",
    model_name="claude-sonnet-4-6"
)

analysis_agent = Agent(
    agent_name="Analysis-Specialist",
    system_prompt="Expert in data analysis",
    model_name="claude-sonnet-4-6"
)

writing_agent = Agent(
    agent_name="Writing-Specialist",
    system_prompt="Expert in writing and communication",
    model_name="claude-sonnet-4-6"
)

# Create hierarchical swarm
swarm = HierarchicalSwarm(
    name="Research-Analysis-Team",
    description="A hierarchical team for research and analysis",
    agents=[research_agent, analysis_agent, writing_agent],
    max_loops=2,
    director_settings={
        "model_name": "claude-sonnet-4-6",
        "temperature": 0.2,
        "top_p": None,
        "max_tokens": 4000,
    },
    max_agent_retries=1,
    max_reassignment_attempts=1,
)

# Display the hierarchy
swarm.display_hierarchy()

# Execute a task
result = swarm.run(
    task="Analyze the impact of AI on healthcare and create a comprehensive report"
)

print(result)
```

## Conversation Autosave

When `autosave=True`, the directory is created at construction and the conversation history is saved at the end of every `run()`, including a failed one:
`$WORKSPACE_DIR/swarms/HierarchicalSwarm/{swarm-name}-{timestamp}/conversation_history.json`

`WORKSPACE_DIR` defaults to `./agent_workspace`. Each run overwrites the same file.

This enables:
- Post-execution analysis
- Debugging and monitoring
- Historical tracking of swarm operations
