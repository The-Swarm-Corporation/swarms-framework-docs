## Overview

The `GraphWorkflow` class represents a workflow graph where each node is an agent. It provides sophisticated capabilities for building, executing, and visualizing Directed Acyclic Graph (DAG) workflows with automatic parallel execution, topological sorting, and compilation optimization.

## Key Features

- **DAG-Based Workflows**: Build complex directed acyclic graphs of agent execution
- **Automatic Parallelization**: Automatically execute independent agents in parallel
- **Topological Execution**: Agents execute in topologically sorted layers
- **Compilation Optimization**: Pre-compute execution plans for faster multi-loop execution
- **Multiple Graph Backends**: Support for NetworkX and Rustworkx backends
- **Visualization**: Generate visual representations of workflows using Graphviz
- **Fan-Out/Fan-In Patterns**: Easy creation of parallel processing patterns
- **JSON Serialization**: Save and load workflows to/from JSON
- **Async Support**: Asynchronous execution for non-blocking operations
- **Cycle Detection**: Automatic detection and reporting of cycles
- **Nested Workflows**: Run a whole `GraphWorkflow` as a single node
- **Checkpoints**: Resume an interrupted run from its last completed layer
- **Token Usage**: Sum token spend across every node and subgraph with `usage`

## Methods

### Graph Construction

#### `add_node(agent, **kwargs)`

Add an agent, or a nested `GraphWorkflow`, as a node in the workflow graph. An agent node's ID is its `agent_name`. A nested workflow becomes a `SUBGRAPH` node whose ID is the inner workflow's `name`; it is compiled on insertion if needed. Raises `ValueError` if a node with the same ID already exists.

<ParamField path="agent" type="Union[Agent, GraphWorkflow]" required>
  The agent or inner workflow to add. Pass the object itself, not a `Node`; to supply prebuilt `Node` objects, use the `nodes` constructor argument or `from_spec()`.
</ParamField>

<ParamField path="**kwargs" type="Any">
  Additional keyword arguments for the node, such as `metadata`
</ParamField>

#### `add_nodes(agents, batch_size=10, **kwargs)`

Add multiple agents to the workflow graph concurrently in batches.

<ParamField path="agents" type="List[Agent]" required>
  List of agents to add
</ParamField>

<ParamField path="batch_size" type="int" default="10">
  Number of agents to add concurrently in a batch
</ParamField>

#### `add_edge(edge_or_source, target=None, **kwargs)`

Add an edge by Edge object or by passing node objects/ids.

<ParamField path="edge_or_source" type="Union[Edge, Node, Agent, str]" required>
  Either an Edge object or the source node/id
</ParamField>

<ParamField path="target" type="Optional[Union[Node, Agent, str]]">
  Target node/id (required if edge_or_source is not an Edge)
</ParamField>

#### `add_edges_from_source(source, targets, **kwargs)`

Add multiple edges from a single source to multiple targets (fan-out pattern).

<ParamField path="source" type="Union[Node, Agent, str]" required>
  Source node/id that will send output to multiple targets
</ParamField>

<ParamField path="targets" type="List[Union[Node, Agent, str]]" required>
  List of target node/ids that will receive the source output in parallel
</ParamField>

<ResponseField name="edges" type="List[Edge]">
  List of created Edge objects
</ResponseField>

#### `add_edges_to_target(sources, target, **kwargs)`

Add multiple edges from multiple sources to a single target (fan-in pattern).

<ParamField path="sources" type="List[Union[Node, Agent, str]]" required>
  List of source node/ids that will send output to the target
</ParamField>

<ParamField path="target" type="Union[Node, Agent, str]" required>
  Target node/id that will receive all source outputs
</ParamField>

<ResponseField name="edges" type="List[Edge]">
  List of created Edge objects
</ResponseField>

#### `add_parallel_chain(sources, targets, **kwargs)`

Create a parallel processing chain (full mesh connection).

<ParamField path="sources" type="List[Union[Node, Agent, str]]" required>
  List of source node/ids
</ParamField>

<ParamField path="targets" type="List[Union[Node, Agent, str]]" required>
  List of target node/ids
</ParamField>

<ResponseField name="edges" type="List[Edge]">
  List of created Edge objects
</ResponseField>

### Execution

#### `run(task=None, img=None, on_node_complete=None, streaming_callback=None, *args, **kwargs)`

Run the workflow graph with optimized parallel agent execution. The graph is compiled first if it is not already. Each node receives the task plus one chat turn per predecessor output. When `max_loops > 1`, end-point outputs from each loop are fed as additional context into the next loop so agents can iteratively refine their results.

A node that raises does not stop the run: its output becomes an `"[ERROR] Agent <name> failed: ..."` string, and downstream nodes still run. A subgraph node's output is the inner workflow's results joined as `[node_id]: output` blocks.

<ParamField path="task" type="Optional[str]">
  Task to execute. Uses self.task if not provided.
</ParamField>

<ParamField path="img" type="Optional[str]">
  Optional image path for multimodal tasks
</ParamField>

<ParamField path="on_node_complete" type="Optional[Callable[[str, Any], None]]" default="None">
  Callback fired immediately when each agent finishes, before the layer completes. Receives `(node_id, output)`. Takes precedence over the instance-level callback set in `__init__`.
</ParamField>

<ParamField path="streaming_callback" type="Optional[Callable[[str, str], None]]" default="None">
  Callback fired for every token as agents generate output in real time. Receives `(node_id, token)`.
</ParamField>

<ResponseField name="results" type="Dict[str, Any]">
  Execution results for every node, not only the end points, keyed by node ID. When `max_loops == 1`, returns the single loop's results. When `max_loops > 1`, returns a dict with per-loop results keyed as `{node_id}_loop_{loop_number}` plus the final loop's results under the plain `node_id` keys.
</ResponseField>

#### `arun(task=None, *args, **kwargs)`

Async version of `run()`. Runs `run()` in a worker thread with `asyncio.to_thread`, forwarding any extra arguments.

<ParamField path="task" type="Optional[str]">
  Task to execute. Uses self.task if not provided.
</ParamField>

<ResponseField name="results" type="Dict[str, Any]">
  Execution results from all nodes
</ResponseField>

#### `usage` (property)

Provider token usage summed over every agent in the graph, including the agents inside nested subgraphs at any depth. An agent that backs several nodes, or appears in both this graph and a subgraph, is counted once. See [Token usage](/agents/token-usage).

<ResponseField name="usage" type="dict">
  A new dict with `input_tokens`, `output_tokens`, `cached_tokens`, `reasoning_tokens` and `total_tokens`. Agent totals are lifetime totals, so the value grows across repeated `run()` / `arun()` calls and includes anything a shared agent spent in other workflows.
</ResponseField>

```python
results = workflow.run("Research AI trends in healthcare")
print(workflow.usage["total_tokens"])
```

### Compilation and Optimization

#### `compile()`

Pre-compute expensive operations for faster execution: auto-set missing entry and end points, compute topological layers and run the structural checks from `validate()`, logging any problems without raising. Results are cached until the graph changes; adding a node or edge, or setting entry or end points, invalidates the cache and the next `run()` recompiles.

#### `get_compilation_status()`

Get detailed compilation status information.

<ResponseField name="status" type="Dict[str, Any]">
  Compilation status including cache state, timestamps, and performance metrics
</ResponseField>

### Serialization

Workflows serialize in two shapes. A **shallow** spec stores the topology only: each node names its agent by `agent_name`, so you supply the live agents when loading. A **deep** export embeds each agent's `to_dict()` output plus export metadata and metrics.

#### `to_dict(shallow=True, include_conversation=False, include_runtime_state=False)`

Serialize the workflow to a dict. This is the builder behind `to_spec()`, `to_json()`, `save()` and `save_to_file()`.

<ParamField path="shallow" type="bool" default="True">
  `True` for the sorted, diffable topology spec. `False` for a deep export with agents embedded.
</ParamField>

<ParamField path="include_conversation" type="bool" default="False">
  Deep shape only. Embed the conversation history.
</ParamField>

<ParamField path="include_runtime_state" type="bool" default="False">
  Deep shape only. Embed the compilation state.
</ParamField>

#### `save(path, shallow=True, overwrite=True, include_conversation=False, include_runtime_state=False)`

Write `to_dict(...)` to a JSON file, creating parent directories. Raises `FileExistsError` if the file exists and `overwrite=False`. Pair with `load()`.

<ResponseField name="path" type="str">
  The path written
</ResponseField>

#### `load(path, agent_registry=None, restore_runtime_state=False, **kwargs)` (classmethod)

Read a file written by `save()`, `save_spec()` or `save_to_file()`, detecting which shape it holds. Raises `FileNotFoundError` if the file does not exist.

<ParamField path="agent_registry" type="Optional[Dict[str, Agent]]" default="None">
  Mapping from `agent_name` to live `Agent`. Required for a shallow spec (`ValueError` without it). Optional for a deep export; without it, deep-loaded nodes hold plain dicts instead of runnable agents.
</ParamField>

<ParamField path="restore_runtime_state" type="bool" default="False">
  Deep exports only. Restore the saved compilation state.
</ParamField>

<ResponseField name="workflow" type="GraphWorkflow">
  The reconstructed workflow
</ResponseField>

#### `to_json(fast=True, include_conversation=False, include_runtime_state=False)`

Serialize the workflow to a deep JSON export with agents embedded.

<ParamField path="fast" type="bool" default="True">
  Ignored; kept for backward compatibility
</ParamField>

<ParamField path="include_conversation" type="bool" default="False">
  Whether to include conversation history
</ParamField>

<ParamField path="include_runtime_state" type="bool" default="False">
  Whether to include runtime state like compilation info
</ParamField>

<ResponseField name="json_string" type="str">
  JSON representation of the workflow
</ResponseField>

#### `from_json(json_str, restore_runtime_state=False, agent_registry=None)` (classmethod)

Deserialize a workflow from a deep JSON export. Nodes keep their exported IDs, so edges resolve. Raises `ValueError` if `json_str` is not valid JSON.

<ParamField path="json_str" type="str" required>
  JSON string produced by `to_json()`
</ParamField>

<ParamField path="restore_runtime_state" type="bool" default="False">
  Whether to restore runtime state
</ParamField>

<ParamField path="agent_registry" type="Optional[Dict[str, Agent]]" default="None">
  Mapping from `agent_name` to live `Agent`. Nodes whose agent is not in the registry hold the exported agent dict, which cannot run.
</ParamField>

<ResponseField name="workflow" type="GraphWorkflow">
  A new GraphWorkflow instance
</ResponseField>

#### `save_to_file(filepath, include_conversation=False, include_runtime_state=False, overwrite=False)`

Save a deep export (agents embedded) to a JSON file. Appends `.json` when the path lacks it.

<ParamField path="filepath" type="str" required>
  Path to save the JSON file
</ParamField>

<ParamField path="overwrite" type="bool" default="False">
  Whether to overwrite an existing file. When `False`, an existing file raises `FileExistsError`.
</ParamField>

<ResponseField name="filepath" type="str">
  Path to the saved file
</ResponseField>

#### `load_from_file(filepath, restore_runtime_state=False)` (classmethod)

Load a workflow from a JSON file. Equivalent to `load(filepath, restore_runtime_state=...)` with no agent registry, so a deep export comes back with plain-dict agents. Use `load(path, agent_registry=...)` when you need a runnable workflow.

<ParamField path="filepath" type="str" required>
  Path to the JSON file
</ParamField>

<ResponseField name="workflow" type="GraphWorkflow">
  Loaded workflow instance
</ResponseField>

### Validation

#### `validate(auto_fix=False, raise_on_error=False)`

Validate the workflow structure, checking for isolated nodes, cyclic dependencies, unreachable nodes, dead-end nodes, and missing entry/end points.

<ParamField path="auto_fix" type="bool" default="False">
  Whether to automatically fix simple issues (e.g. auto-setting missing entry/exit points, adding unreachable nodes to entry points)
</ParamField>

<ParamField path="raise_on_error" type="bool" default="False">
  When `True`, raises a `ValueError` if validation determines the workflow is invalid. Defaults to `False` so existing callers that inspect the returned dict are unaffected.
</ParamField>

<ResponseField name="validation_result" type="Dict[str, Any]">
  Dictionary containing `is_valid`, `errors`, `warnings`, `fixed`, and (when cycles are found) `cycles`
</ResponseField>

### Checkpoints and Spec Serialization

<ParamField path="task" type="str" required>

<ResponseField name="deleted_count" type="int">

</ResponseField>

- `ValueError`: If `checkpoint_dir` was not set on this workflow instance

#### `save_spec(path)`

Save the topology spec produced by `to_spec()` to a JSON file.

<ParamField path="agent_registry" type="Dict[str, Agent]" required>

## Usage Examples

### Basic Sequential Graph

```python
from swarms import Agent, GraphWorkflow

# Create agents
researcher = Agent(
    agent_name="Researcher",
    model_name="claude-sonnet-4-6",
    system_prompt="Research and gather information"
)

analyzer = Agent(
    agent_name="Analyzer",
    model_name="claude-sonnet-4-6",
    system_prompt="Analyze the research findings"
)

writer = Agent(
    agent_name="Writer",
    model_name="claude-sonnet-4-6",
    system_prompt="Write based on analysis"
)

# Create workflow
workflow = GraphWorkflow(
    name="Research-Analyze-Write",
    description="Sequential research workflow"
)

# Add nodes
workflow.add_node(researcher)
workflow.add_node(analyzer)
workflow.add_node(writer)

# Add edges
workflow.add_edge("Researcher", "Analyzer")
workflow.add_edge("Analyzer", "Writer")

# Compile and run
workflow.compile()
results = workflow.run("Research AI trends in healthcare")
```

### Fan-Out Pattern (Parallel Specialists)

```python
# Create multiple specialist agents
technical = Agent(agent_name="Technical", model_name="gpt-5.4-mini", system_prompt="Technical analysis")
business = Agent(agent_name="Business", model_name="gpt-5.4-mini", system_prompt="Business analysis")
user_exp = Agent(agent_name="UX", model_name="gpt-5.4-mini", system_prompt="User experience analysis")
synthesizer = Agent(agent_name="Synthesizer", model_name="gpt-5.4", system_prompt="Synthesize all analyses")

workflow = GraphWorkflow(name="Multi-Perspective")

# Add all nodes
for agent in [researcher, technical, business, user_exp, synthesizer]:
    workflow.add_node(agent)

# Fan-out from researcher to specialists
workflow.add_edges_from_source(
    "Researcher",
    ["Technical", "Business", "UX"]
)

# Fan-in to synthesizer
workflow.add_edges_to_target(
    ["Technical", "Business", "UX"],
    "Synthesizer"
)

results = workflow.run("Analyze AI chatbot implementation")
```

### Complex DAG Workflow

```python
# Create a complex multi-stage workflow
data_collector = Agent(agent_name="DataCollector", model_name="gpt-5.4-mini")
preprocessor = Agent(agent_name="Preprocessor", model_name="gpt-5.4-mini")
model_a = Agent(agent_name="ModelA", model_name="gpt-5.4-mini")
model_b = Agent(agent_name="ModelB", model_name="gpt-5.4-mini")
model_c = Agent(agent_name="ModelC", model_name="gpt-5.4-mini")
ensemble = Agent(agent_name="Ensemble", model_name="gpt-5.4")
validator = Agent(agent_name="Validator", model_name="gpt-5.4")

workflow = GraphWorkflow(name="ML-Pipeline")

# Add all nodes
agents = [data_collector, preprocessor, model_a, model_b, model_c, ensemble, validator]
workflow.add_nodes(agents, batch_size=5)

# Build DAG
workflow.add_edge("DataCollector", "Preprocessor")
workflow.add_edges_from_source("Preprocessor", ["ModelA", "ModelB", "ModelC"])
workflow.add_edges_to_target(["ModelA", "ModelB", "ModelC"], "Ensemble")
workflow.add_edge("Ensemble", "Validator")

# Visualize before running
workflow.visualize(show_summary=True)

# Execute
results = workflow.run("Predict customer churn")
```

### Using from_spec for Quick Construction

```python
# Quick workflow construction using from_spec
agents = [researcher, analyzer, writer]

edges = [
    ("Researcher", "Analyzer"),
    ("Analyzer", "Writer")
]

workflow = GraphWorkflow.from_spec(
    agents=agents,
    edges=edges,
    name="Quick-Workflow",

```

### Advanced Edge Patterns in from_spec

```python
agents = [collector, analyst1, analyst2, analyst3, synthesizer]

edges = [
    # Simple edge
    ("Collector", "Analyst1"),
    
    # Fan-out
    ("Collector", ["Analyst2", "Analyst3"]),
    
    # Fan-in

```

### Async Execution

```python
import asyncio

async def run_workflow():
    workflow = GraphWorkflow(name="Async-Workflow")
    workflow.add_nodes([agent1, agent2, agent3])
    workflow.add_edge("agent1", "agent2")
    workflow.add_edge("agent2", "agent3")
    
    results = await workflow.arun("Process this task asynchronously")
    return results

results = asyncio.run(run_workflow())
```

### Save and Load Workflows

Agents hold live LLM clients, so a saved file can't recreate them. Save the topology and pass the live agents back in when you load:

```python
# Topology only: each node stores its agent_name
workflow.save("my_workflow.json")

loaded_workflow = GraphWorkflow.load(
    "my_workflow.json",
    agent_registry={"Researcher": researcher, "Analyzer": analyzer, "Writer": writer},
)

results = loaded_workflow.run("New task")
```

A deep export also round-trips, with the same registry needed to make it runnable:

```python
workflow.save_to_file(
    "my_workflow_full.json",
    include_runtime_state=True,
    overwrite=True,
)

loaded_workflow = GraphWorkflow.load(
    "my_workflow_full.json",
    agent_registry={"Researcher": researcher, "Analyzer": analyzer, "Writer": writer},
    restore_runtime_state=True,
)
```

</Warning>

## Node and Edge Classes

### Node

A node wraps an `Agent` (`NodeType.AGENT`) or a nested `GraphWorkflow` (`NodeType.SUBGRAPH`). When `id` is omitted, it defaults to the agent's `agent_name` or the workflow's `name`.

```python
from swarms import Node, NodeType

# Create node from agent
node = Node.from_agent(agent)

# Create node from a nested workflow
sub_node = Node.from_subgraph(inner_workflow, node_id="research-stage")

# Create node manually
node = Node(
    id="my-node",
    type=NodeType.AGENT,
    agent=agent,
    metadata={"custom_key": "custom_value"}
)

# Prebuilt nodes go in through the constructor; add_node() takes the agent itself
workflow = GraphWorkflow(nodes={node.id: node})
```

### Edge

```python
from swarms import Edge

# Create edge from nodes
edge = Edge.from_nodes(source_agent, target_agent)

# Create edge from IDs
edge = Edge(source="agent1", target="agent2")

# With metadata
edge = Edge(
    source="agent1",
    target="agent2",
    metadata={"weight": 1.0}
)
```

### Nested workflows (subgraphs)

Pass a `GraphWorkflow` to `add_node()` to run it as a single node. The inner workflow receives the outer node's prompt as its task, and its results are joined into one output for downstream nodes. `usage` and `to_spec()` include subgraphs.

```python
research = GraphWorkflow(name="ResearchStage")
research.add_node(researcher)
research.add_node(analyzer)
research.add_edge("Researcher", "Analyzer")

pipeline = GraphWorkflow(name="Pipeline")
pipeline.add_node(research)  # node id "ResearchStage"
pipeline.add_node(writer)
pipeline.add_edge("ResearchStage", "Writer")

results = pipeline.run("Research AI trends in healthcare")
```

## Best Practices

1. **Compilation**: `run()` compiles on demand; call `compile()` yourself to surface validation warnings before the first run
2. **Visualization**: Use `visualize()` to understand your workflow structure
3. **Validation**: Validate workflows before production deployment
4. **Entry/Exit Points**: Let the system auto-detect entry/exit points or set them explicitly
5. **Backend Selection**: Use Rustworkx for large graphs (>100 nodes)
6. **Error Handling**: Wrap execution in try-except blocks
7. **Batching**: Use `add_nodes()` with appropriate batch sizes for many agents
8. **Caching**: Enable `auto_compile` for multi-loop workflows
9. **Save Progress**: Save complex workflows with `save()` and reload them with `load(path, agent_registry=...)`
10. **Cost Tracking**: Read `workflow.usage` after a run to see token spend across every node

## Performance Characteristics

- **Parallel Execution**: Independent agents in the same layer run concurrently
- **Thread Pool**: One pool per run, sized to `max_parallel_nodes` (default ~95% of CPU cores) and capped at the widest layer
- **Compilation**: Pre-computes execution plan, cached for multi-loop runs
- **Memory**: Each agent maintains its own context
- **Graph Backend**: Rustworkx is faster for large graphs (>100 nodes)
