## Overview

The `SwarmRouter` class dispatches tasks to any supported multi-agent architecture through a single, uniform interface. Set `swarm_type` to choose the architecture; pass the same agent list and call `run(task)` regardless of which architecture you select.

It also handles:

- Validated construction of the underlying swarm (`reliability_check`)
- Fallback to other swarm types when the primary one fails (`fallback_swarms`)
- Token usage summed across every agent the swarm ran (`usage`)
- Optional autosave of config / state / metadata to the workspace
- Multi-agent collaboration prompt injection
- O(1) factory dispatch with internal caching

## Import

```python
from swarms import SwarmRouter, SwarmType
from swarms.structs.swarm_router import (
    SwarmRouterConfig,
    SwarmRouterRunError,
    SwarmRouterConfigError,
)
```

## `SwarmType`

`SwarmType` is a `typing.Literal` enumerating every accepted `swarm_type` string. Any value outside this set raises `SwarmRouterConfigError` at construction time.

```python
SwarmType = Literal[
    "AgentRearrange",
    "MixtureOfAgents",
    "SequentialWorkflow",
    "ConcurrentWorkflow",
    "GroupChat",
    "MultiAgentRouter",
    "HierarchicalSwarm",
    "MajorityVoting",
    "CouncilAsAJudge",
    "HeavySwarm",
    "LLMCouncil",
    "DebateWithJudge",
    "RoundRobin",
    "PlannerWorkerSwarm",
]
```

<Note>
  `"AutoSwarmBuilder"` is **not** in the `SwarmType` Literal — passing it raises `SwarmRouterConfigError` at construction. Neither `"auto"` nor `"BatchedGridWorkflow"` is a member either (14 values total) — passing either raises `SwarmRouterConfigError` at construction time, the same as any other invalid value.
</Note>

    id: Optional[str] = None,  # resolves to generate_id("swarm-router") when not set

    agents: List[Union[Agent, Callable]] = [],

    fallback_swarms: Optional[List[SwarmType]] = None,

    heavy_swarm_swarm_show_output: bool = True,

### Core parameters

<ParamField path="id" type="Optional[str]" default="None">
  Unique identifier for the router instance. When left as `None`, resolves to `generate_id("swarm-router")`. Used for autosave directory naming and telemetry.
</ParamField>

<ParamField path="name" type="str" default="swarm-router">
  Human-readable name. Used for autosave directory naming.
</ParamField>

<ParamField path="description" type="str" default="Routes your task to the desired swarm">
  Free-form description of the router's purpose.
</ParamField>

<ParamField path="agents" type="List[Union[Agent, Callable]]" default="[]">
  Agents the router will pass to the selected swarm. Some swarm types require a specific minimum count (e.g. `DebateWithJudge` needs at least three).
</ParamField>

<ParamField path="swarm_type" type="SwarmType" default="SequentialWorkflow">
  Which architecture to instantiate. See the `SwarmType` Literal above.
</ParamField>

<ParamField path="max_loops" type="int" default="1">
  Maximum execution loops where supported by the underlying swarm (e.g. `HierarchicalSwarm`, `GroupChat`). For `MixtureOfAgents` it is the number of layers. `HeavySwarm` uses `heavy_swarm_max_loops` instead, and `CouncilAsAJudge`, `LLMCouncil`, and `MultiAgentRouter` do not receive it. Cannot be `0`.
</ParamField>

<ParamField path="output_type" type="OutputType" default="dict">
  Output formatter applied to the conversation. One of `'list'`, `'dict'`, `'dictionary'`, `'string'`, `'str'`, `'final'`, `'last'`, `'json'`, `'all'`, `'yaml'`, `'dict-all-except-first'`, `'str-all-except-first'`, `'basemodel'`, `'dict-final'`, `'list-final'`. `HeavySwarm`, `DebateWithJudge`, `CouncilAsAJudge`, and `LLMCouncil` receive it too; `RoundRobin` does not.
</ParamField>

<ParamField path="fallback_swarms" type="Optional[List[SwarmType]]" default="None">
  Swarm types to try, in order, when the primary `swarm_type` raises while being built or run. Each fallback is built from the same agents and configuration and receives the same payload; the first to complete wins. If every swarm fails, `SwarmRouterRunError` is raised listing each attempt, with the last error as its cause. Validated at construction: it must be a list of valid `SwarmType` strings, and `rearrange_flow` must be set if it includes `"AgentRearrange"`. When `None`, the primary swarm's error propagates unchanged. See [Fallback swarms](#fallback-swarms).
</ParamField>

### Behavior modifiers

<ParamField path="multi_agent_collab_prompt" type="bool" default="False">
  Deliver the built-in collaboration prompt to each agent so they understand they are part of a multi-agent team. It is passed to the swarm at construction and reaches the agents as a **system turn** at run time; the caller's `Agent` objects are never modified.

  Only `SequentialWorkflow` and `AgentRearrange` can deliver it. For any other `swarm_type` a warning is logged and the flag has no effect.
</ParamField>

<ParamField path="list_all_agents" type="bool" default="False">
  When `True`, every agent receives a manifest of its peers (name + description) in the same system turn as the collaboration prompt. Like the collaboration prompt, it is only delivered by `SequentialWorkflow` and `AgentRearrange`; other swarm types ignore it without a warning.
</ParamField>

<ParamField path="conversation" type="Any" optional>
  Stored as `router.conversation`. It is not passed to the underlying swarm. After each run, `router.conversation` is repointed at the swarm's own conversation.
</ParamField>

<ParamField path="channel" type="CommsChannel" default="None">
  A shared channel, such as `FileChannel("runs/q3.md")`. Forwarded to the swarm the router builds, which seeds its conversation from the channel, then posts the task and every agent's answer to it under the speaker's name. Member agents' own `channel` settings are detached with a warning, so only the swarm posts. See [Comms Channel](/agents/comms-channel#multi-agent-structures).
</ParamField>

<ParamField path="agents_config" type="Optional[Dict[Any, Any]]" optional>
  Stored as `router.agents_config`. No swarm factory reads it.
</ParamField>

<ParamField path="verbose" type="bool" default="False">
  Emit detailed logs during construction and execution.
</ParamField>

### Autosave

<ParamField path="autosave" type="bool" default="False">
  When enabled, persist `config.json` on construction and `state.json` + `metadata.json` after each run to `{workspace_dir}/swarms/SwarmRouter/{swarm-name}-{stamp}/`.
</ParamField>

<ParamField path="autosave_use_timestamp" type="bool" default="True">
  Use a `YYYYmmdd_HHMMSS` timestamp in the directory name when `True`; use a 12-character UUID fragment when `False`.
</ParamField>

### Per-architecture parameters

These are only consulted when the corresponding `swarm_type` is selected.

#### AgentRearrange

<ParamField path="rearrange_flow" type="str" required>
  Flow DSL string, e.g. `"researcher -> writer, editor"`. Required for `swarm_type="AgentRearrange"`.
</ParamField>

#### GroupChat

`GroupChat` is asynchronous and self-selecting — there are **no speaker-selection functions**. The router passes `agents`, `max_loops`, `output_type`, and `verbose` through to it; agents decide on their own whether to speak. See the [GroupChat API reference](/api/group-chat) for `threshold` / `idle_timeout` tuning (configure those by constructing the `GroupChat` directly).

#### HeavySwarm

<ParamField path="heavy_swarm_question_agent_model_name" type="str" default="gpt-5.4">
  Model used by the question-generation agent.
</ParamField>

<ParamField path="heavy_swarm_worker_model_name" type="str" default="gpt-5.4">
  Model used by every worker agent.
</ParamField>

<ParamField path="heavy_swarm_swarm_show_output" type="bool" default="True">
  Print per-agent output during execution (`agent_prints_on`). The live dashboard is forced off when `HeavySwarm` is created through the router.
</ParamField>

<ParamField path="heavy_swarm_variant" type='SwarmVariant ("default" | "medium" | "heavy")' default='"default"'>
  Which agent line-up to instantiate: `"default"` → 5 agents, `"medium"` → 4 agents (Captain + Harper / Benjamin / Lucas), `"heavy"` → 16 agents (Grok captain + 15 specialists). `SwarmVariant` is exported from `swarms.agents.heavy_swarm_agents`.
</ParamField>

<ParamField path="heavy_swarm_max_loops" type="int" default="1">
  Number of iterative-refinement loops for `HeavySwarm`.
</ParamField>

<ParamField path="heavy_swarm_timeout" type="int" default="900">
  Per-worker wall-clock cap, in seconds, for `HeavySwarm`.
</ParamField>

<ParamField path="worker_tools" type="List[Callable]" optional>
  Tools made available to every worker agent in `HeavySwarm`.
</ParamField>

#### HierarchicalSwarm

<ParamField path="director_model_name" type="str" default="gpt-5.4">
  Model used by the auto-created director agent. Forwarded to `HierarchicalSwarm` by `_create_hierarchical_swarm()`.
</ParamField>

<ParamField path="director_settings" type="Dict[str, Any]" optional>
  Extra `Agent` keyword arguments for the auto-created director. Every key is forwarded to the director's `Agent`; `agent_name`, `model_name`, `system_prompt`, `temperature`, and `top_p` override the corresponding defaults — including `director_model_name`. A `planning_system_prompt` key sets the planning director's prompt instead.
</ParamField>

#### CouncilAsAJudge

<ParamField path="council_judge_model_name" type="str" default="gpt-5.4">
  Passed to `CouncilAsAJudge` as `model_name`, so it sets the model for every dimension judge. The aggregator keeps `CouncilAsAJudge`'s own `aggregation_model_name` default (`"gpt-5.4"`), which `SwarmRouter` does not expose.
</ParamField>

#### LLMCouncil

<ParamField path="chairman_model" type="str" default="gpt-5.1">
  Model used by the chairman that synthesizes the council members' responses.
</ParamField>

### Additional kwargs

The constructor accepts arbitrary `*args` / `**kwargs` for forward-compatibility, but they are **not** stored on the router or forwarded to the underlying swarm — extra constructor kwargs are effectively ignored. Configure the underlying swarm through the router's explicit parameters listed above.

For `MixtureOfAgents`, the aggregator is **not** passed as a kwarg; the **last agent** in `agents` is used as the aggregator automatically:

```python
router = SwarmRouter(
    swarm_type="MixtureOfAgents",
    agents=[worker_1, worker_2, aggregator],  # aggregator = agents[-1]
)
```

## Exceptions

<ResponseField name="SwarmRouterConfigError" type="Exception">
  Raised by `reliability_check()` when construction inputs are invalid: `swarm_type` is `None`, not a string, or not a `SwarmType` member; `rearrange_flow` is missing for `AgentRearrange`; `max_loops == 0`; or `fallback_swarms` is not a list of valid swarm types.
</ResponseField>

<ResponseField name="SwarmRouterRunError" type="Exception">
  Raised by `run()` only when `fallback_swarms` is set and every swarm in the chain fails. The message names each attempt, and `__cause__` is the last error. Without `fallback_swarms`, `run()` re-raises whatever the swarm raised.
</ResponseField>

If the selected factory itself raises while building the swarm, the error is wrapped in a `RuntimeError` (`"Failed to create swarm ..."`). `batch_run()` wraps any per-task failure in a `RuntimeError`.

## Methods

### `run(task=None, img=None, tasks=None, *args, **kwargs)`

Execute a single task using the configured swarm.

<ParamField path="task" type="str" optional>
  The task to be executed. Required for most `swarm_type` values.
</ParamField>

<ParamField path="img" type="str" optional>
  Optional image input forwarded to vision-capable agents.
</ParamField>

<ParamField path="tasks" type="List[str]" optional>
  Batch-style task list, forwarded as `tasks=` to the underlying swarm's `run()` in place of `task` when provided. Only meaningful for swarm types whose `run()` accepts a `tasks` argument.
</ParamField>

Extra `**kwargs` are forwarded to the underlying swarm's `run()`. `img` is forwarded only when it is set. Each call is recorded as a `SwarmRouter.run` trace span when [telemetry](/deployment/telemetry) is enabled.

**Returns:** `Any` — shape depends on `output_type` and the underlying swarm.

**Raises:** the swarm's own exception, or `SwarmRouterRunError` when `fallback_swarms` is set and every swarm fails.

```python
result = router.run("Analyse Q1 market trends.")
```

---

### `__call__(task, img=None, imgs=None, *args, **kwargs)`

Alias for `run`. Lets you treat a router as a callable. `imgs` is forwarded to the swarm's `run()` as `imgs=` only when you pass it, so swarms whose `run()` has no `imgs` parameter still work.

```python
result = router("Analyse Q1 market trends.")
```

---

### `batch_run(tasks, img=None, imgs=None, *args, **kwargs)`

Execute many tasks sequentially by calling `run()` once per task. The cached swarm is reused across tasks.

<ParamField path="tasks" type="List[str]" required>
  Tasks to process.
</ParamField>

<ParamField path="img" type="str" optional>
  Single image applied to every task.
</ParamField>

<ParamField path="imgs" type="List[str]" optional>
  Forwarded unchanged as `imgs=` to every `run()` call, and only when given. It is not split per task; use `concurrent_run()` for one image per task.
</ParamField>

**Returns:** `List[Any]` — results in the same order as `tasks`.

**Raises:** `RuntimeError` wrapping the first failure.

```python
results = router.batch_run([
    "Summarize Q1.",
    "Summarize Q2.",
    "Summarize Q3.",
])
```

---

### `concurrent_run(tasks, imgs=None, *args, **kwargs)`

Execute `tasks` through `run()` in parallel on a thread pool sized to `os.cpu_count()`. The concurrent counterpart to `batch_run()`. The tracing context follows each task into its worker thread.

<ParamField path="tasks" type="List[str]" required>
  Tasks to execute in parallel.
</ParamField>

<ParamField path="imgs" type="List[str]" optional>
  One image per task, paired by position. Must be the same length as `tasks`, or `ValueError` is raised.
</ParamField>

**Returns:** `List[Any]` — one result per task, in task order.

```python
results = router.concurrent_run([
    "Summarize Q1.",
    "Summarize Q2.",
])
```

---

### `reliability_check()`

Validates the configuration (swarm type, `rearrange_flow`, `max_loops`, `fallback_swarms`) and then runs `setup()`. Called automatically at the end of `__init__`; you do not normally call it yourself. Raises `SwarmRouterConfigError` on invalid input.

---

### `setup()`

Logs a warning when `multi_agent_collab_prompt=True` is set for a swarm type that cannot deliver it. It does not modify the agents: the collaboration preamble is passed to the swarm when it is built. Called automatically during construction via `reliability_check()`. The underlying swarm itself is created lazily on the first `run()`.

---

### `to_dict()`

Serialize the router's configuration and current state to a dictionary suitable for logging or persistence.

**Returns:** `Dict[str, Any]`.

```python
config = router.to_dict()
```

---

### `fetch_message_history_as_string()`

Return the underlying swarm's conversation as a single string, excluding the first message. Call it after at least one `run()`. Returns `None` if no history is available.

---

### `list_agents_to_eachother()`

Internal helper. Points `self.conversation` at the underlying swarm's conversation. Called after each run, because the swarm is built lazily on the first `run()` and several structures replace their conversation object per task. Rarely called directly.

<Note>
  `update_system_prompt_for_agent_in_swarm()` was removed. It appended the collaboration prompt to each agent's `system_prompt` **after** the LLM had been built, so the text never reached the model, while accumulating on the caller's live agents on every construction. The preamble is now passed through the swarm constructor and delivered as a system turn instead.
</Note>

## Required parameters by `swarm_type`

| `swarm_type` | Additional required parameters |
|---|---|
| `SequentialWorkflow` | `agents` (≥1) |
| `ConcurrentWorkflow` | `agents` (≥1) |
| `AgentRearrange` | `agents`, `rearrange_flow` |
| `MixtureOfAgents` | `agents` (workers + aggregator as the **last** element; the full list, aggregator included, also answers as workers) |
| `HierarchicalSwarm` | `agents` (workers); director is created automatically |
| `GroupChat` | `agents` (≥2; asynchronous, self-selecting — no speaker function) |
| `MajorityVoting` | `agents` (≥3 recommended) |
| `CouncilAsAJudge` | `council_judge_model_name` (builds its own agents; `agents` is not passed) |
| `LLMCouncil` | `agents` (council members), `chairman_model` |
| `DebateWithJudge` | `agents` (≥3: pro, con, judge) |
| `HeavySwarm` | `heavy_swarm_worker_model_name`, `heavy_swarm_question_agent_model_name`, `heavy_swarm_variant` |
| `RoundRobin` | `agents` (≥2) |
| `MultiAgentRouter` | `agents` |
| `PlannerWorkerSwarm` | `agents` (workers); planner is created automatically |

<Note>
  `"AutoSwarmBuilder"`, `"auto"`, and `"BatchedGridWorkflow"` are **not** members of the `SwarmType` Literal — passing any of them raises `SwarmRouterConfigError` at construction time, before `run()` is ever reached.
</Note>

## Autosave layout

When `autosave=True`, the router writes to:

```
{workspace_dir}/swarms/SwarmRouter/{name}-{timestamp_or_uuid}/
├── config.json    # written on __init__
├── state.json     # rewritten after each run
└── metadata.json  # rewritten after each run
```

`workspace_dir` is the `WORKSPACE_DIR` environment variable. When it is unset, the router sets it to `./agent_workspace` under the current directory. `metadata.json` records the task, the `swarm_type` that served the run, and any `fallback_attempts`.

## Fallback swarms

Set `fallback_swarms` to keep a run alive when the primary architecture fails. The router tries each type in order and stops at the first one that completes.

```python
from swarms import Agent, SwarmRouter

agents = [
    Agent(agent_name="Researcher", model_name="gpt-5.4", max_loops=1),
    Agent(agent_name="Analyst", model_name="gpt-5.4", max_loops=1),
    Agent(agent_name="Writer", model_name="gpt-5.4", max_loops=1),
]

router = SwarmRouter(
    name="resilient-router",
    agents=agents,
    swarm_type="HierarchicalSwarm",
    fallback_swarms=["SequentialWorkflow", "ConcurrentWorkflow"],
)

result = router.run("Assess whether a SaaS company should adopt usage-based pricing.")

print(router.active_swarm_type)
for attempt in router.fallback_attempts:
    print(attempt["swarm_type"], attempt["error"])
```

Each swarm type is cached under its own key, so later runs reuse whichever swarms were already built.

## Attributes

<ResponseField name="usage" type="dict">
  Provider token usage summed over every distinct `Agent` the router has run: the agents you passed plus any agent a built swarm holds on its own, such as a `HierarchicalSwarm` director, a `MixtureOfAgents` aggregator, or a judge. Keys: `input_tokens`, `output_tokens`, `cached_tokens`, `reasoning_tokens`, `total_tokens`. Agent totals are lifetime totals, so an agent shared with another router contributes what it spent there too. Read-only property. See [Token usage](/agents/token-usage).
</ResponseField>

<ResponseField name="active_swarm_type" type="str">
  The swarm type that served the most recent run. Equal to `swarm_type` unless a fallback was used.
</ResponseField>

<ResponseField name="fallback_attempts" type="List[dict]">
  One `{"swarm_type": str, "error": Exception}` entry per swarm that failed during the most recent run. Empty when the primary swarm succeeded.
</ResponseField>

<ResponseField name="swarm" type="Any">
  The underlying swarm that served the most recent run. `None` until the first `run()`.
</ResponseField>

<ResponseField name="swarm_workspace_dir" type="Optional[str]">
  The autosave directory, or `None` when `autosave=False`.
</ResponseField>

```python
before = router.usage
router.run("Should a fifty-person engineering org adopt a monorepo?")
after = router.usage
print({k: after[k] - before[k] for k in after})
```

## Usage Example

```python
from swarms import Agent, SwarmRouter

researcher = Agent(
    agent_name="Research-Agent",
    system_prompt="You are a research specialist.",
    model_name="claude-sonnet-4-6",
)

analyst = Agent(
    agent_name="Analysis-Agent",
    system_prompt="You analyze research findings into actionable insights.",
    model_name="claude-sonnet-4-6",
)

router = SwarmRouter(
    name="research-analysis-swarm",
    description="A swarm for research + analysis tasks",
    agents=[researcher, analyst],
    swarm_type="SequentialWorkflow",
    max_loops=1,
    autosave=True,
    verbose=True,
)

result = router.run("Research recent trends in AI hardware and analyze them.")
print(result)
```
