## Overview

The `swarms.utils` module provides essential utilities for file operations, logging, output formatting, token counting, and data processing. These utilities support core agent functionality and framework operations.

Every name in `swarms.utils.__all__` is re-exported from the top-level package, so `from swarms import count_tokens` works. Names outside `__all__`, such as `Formatter` and `get_supported_models`, are imported from their modules.

## Logging

### initialize_logger

Initialize a Loguru logger with custom formatting and output configuration.

```python
from swarms import initialize_logger

logger = initialize_logger(log_folder="my_logs")

logger.info("Application started")
logger.error("An error occurred")
logger.debug("Debug information")
```

<ParamField path="log_folder" type="str" default="swarms">
  Legacy parameter, kept only for backwards compatibility — it no longer sets the log directory. Logs are always written to `{WORKSPACE_DIR}/logs` (via `get_log_dir()`), regardless of what is passed here.
</ParamField>

<ResponseField name="return" type="Logger">
  The shared Loguru logger. Handlers are configured on the first call and reused afterwards
</ResponseField>

**Features:**
- Colored console output at `INFO` level
- Timestamp formatting
- Function and line number tracking
- Backtrace and diagnostics enabled
- Thread-safe enqueuing

**Log files:** logs go to `{WORKSPACE_DIR}/logs`, or `agent_workspace/logs` when `WORKSPACE_DIR` is unset. That directory holds a combined `swarms_{YYYY-MM-DD}.log`, rotated daily and kept for 10 days, plus one `{module}.log` per `swarms` module that logs, rolled to `{module}.log.1` past 10 MB. If the directory cannot be created, the logger falls back to console output only.

## Formatting & Output

### Formatter

Rich-based formatter for beautiful console output with markdown support.

```python
from swarms.utils.formatter import Formatter

formatter = Formatter(md=True)

# Print formatted panels
formatter.print_panel(
    "Analysis complete",
    title="Status",
    style="bold green"
)

# Print markdown with syntax highlighting
formatter.print_markdown(
    "# Results\n\n```python\nprint('hello')\n```",
    title="Code Output"
)
```

#### Constructor

<ParamField path="md" type="bool" default="True">
  Enable markdown output rendering
</ParamField>

The module also exposes a ready-made instance, `from swarms.utils.formatter import formatter`, created with `md=False`.

Panel body text renders in a neutral grey (`grey85`), whatever border color or style you choose.

## File Processing

### create_file_in_folder

Create a file with content in a specified folder.

```python
from swarms import create_file_in_folder

file_path = create_file_in_folder(
    folder_path="./reports",
    file_name="analysis.txt",
    content="Financial analysis results..."
)
```

<ParamField path="folder_path" type="str" required>
  Path to the folder (created if doesn't exist)
</ParamField>

<ParamField path="file_name" type="str" required>
  Name of the file to create. A name that resolves outside folder_path, such as an absolute path or one using `..`, raises ValueError.
</ParamField>

<ParamField path="content" type="Any" required>
  Content to write to the file
</ParamField>

<ResponseField name="return" type="str">
  Path to the created file
</ResponseField>

### sanitize_file_path

Clean and sanitize file paths for cross-platform compatibility.

```python
from swarms import sanitize_file_path

safe_path = sanitize_file_path("`C:/Users/file<name>.txt`")
# Returns: C__Users_file_name_.txt
```

Backticks are removed and surrounding whitespace is stripped. Each of `<`, `>`, `:`, `"`, `/`, `\`, `|`, `?` and `*` is replaced with `_`, so path separators are replaced too.

<ParamField path="file_path" type="str" required>
  File path to sanitize
</ParamField>

<ResponseField name="return" type="str">
  Sanitized file path safe for all platforms
</ResponseField>

<Note>
The file helpers in this section log failures and return `None` instead of raising. Check the return value before you use it.
</Note>

<ParamField path="workspace_path" type="str" required>

<ParamField path="output_filename" type="str" required>

<ResponseField name="return" type="str">

</ParamField>

## Token Management

### count_tokens

Count tokens in text using LiteLLM tokenizer.

```python
from swarms import count_tokens

text = "Analyze the financial statements"
token_count = count_tokens(
    text=text,
    model="gpt-5.4"
)
print(f"Tokens: {token_count}")
```

<ParamField path="text" type="str" required>
  Text to count tokens for
</ParamField>

<ParamField path="model" type="str" default="gpt-5.4">
  Model to use for tokenization
</ParamField>

<ParamField path="default_encoder" type="str" default="gpt-5.4">
  Fallback encoder used if tokenizing with `model` fails
</ParamField>

<ResponseField name="return" type="int">
  Number of tokens in the text. Empty or whitespace-only text returns `0`
</ResponseField>

**Raises:** `ValueError` if both the primary model and the fallback encoder fail to tokenize the text.

<Tip>
To see what a run actually cost, read the provider-reported counts on `agent.usage` instead of re-counting text. See [Token usage](/agents/token-usage).
</Tip>

## Context Window Management

### Conversation.dynamic_auto_chunking

Trim the conversation history from the beginning so the remainder fits within the conversation's token budget, using a binary search over token counts. It returns a single trimmed string (the tail of the history that fits), not a list of chunks.

<Note>
This is a **method on `Conversation`**, not a standalone helper — there is no `dynamic_auto_chunking` in `swarms.utils`. The budget and tokenizer come from the `Conversation`'s own `context_length` and `tokenizer_model_name`, so the method itself takes no arguments.
</Note>

```python
from swarms.structs.conversation import Conversation

conversation = Conversation(
    context_length=4000,
    tokenizer_model_name="gpt-5.4",
)

conversation.add("user", "...very long document...")
conversation.add("assistant", "...long analysis...")

trimmed = conversation.dynamic_auto_chunking()
print(f"Trimmed length: {len(trimmed)} chars")
```

<ResponseField name="return" type="str">
  The conversation history trimmed to fit within `context_length` tokens. Returns the full history unchanged if it already fits, or if chunking fails.
</ResponseField>

Relevant `Conversation` constructor parameters:

<ParamField path="context_length" type="int" default="8192">
  Maximum number of tokens allowed in the conversation history
</ParamField>

<ParamField path="tokenizer_model_name" type="str" default="gpt-5.4">
  Model used for token counting
</ParamField>

## Output History Formatting

### history_output_formatter

Format a `Conversation` object's history into one of several output formats. This is what an agent's or swarm's `output_type` setting runs through.

```python
from swarms import history_output_formatter

formatted = history_output_formatter(
    conversation=conversation_history,
    type="str",
)
print(formatted)
```

<ParamField path="conversation" type="Conversation" required>
  A conversation object exposing methods like `return_messages_as_list()`, `to_dict()`, `get_str()`, etc.
</ParamField>

<ParamField path="type" type="HistoryOutputType" default="list">
  Output format. One of: `"list"`, `"dict"`/`"dictionary"`, `"string"`/`"str"`, `"final"`/`"last"`, `"json"`, `"all"` (same as `"str"`), `"yaml"`, `"dict-all-except-first"`, `"str-all-except-first"`, `"dict-final"`, `"list-final"`
</ParamField>

**Raises:** `ValueError` if `type` is not one of the supported values.

`HistoryOutputType` is the `Literal` type listing these values, exported from `swarms.utils` and `swarms` for type hints. `OutputType` in `swarms.utils.output_types` is an alias of it.

<Warning>
The `"xml"` output type and the `swarms.utils.xml_utils` module have been removed, so `"xml"` now raises `ValueError`. Use `"json"` or `"yaml"` for a serialized history. `"basemodel"` is still listed in `HistoryOutputType`, but `history_output_formatter` does not handle it and raises `ValueError`.
</Warning>

## LiteLLM Wrapper

### LiteLLM

Wrapper class for LiteLLM with error handling. `Agent` builds one of these internally; use it directly for single LLM calls outside an agent.

```python
from swarms import LiteLLM

llm = LiteLLM(
    model_name="gpt-5.4",
    temperature=0.7,
    max_tokens=1000
)

response = llm.run("Analyze this data")
print(llm.usage)
```

The constructor parameter is `model_name`, not `model` — because `LiteLLM.__init__` absorbs unrecognized keywords via `**kwargs`, passing `model=` silently fails to set the model instead of raising an error.

Commonly used constructor parameters:

<ParamField path="model_name" type="str" default="gpt-5.4">
  Any LiteLLM model string
</ParamField>

<ParamField path="system_prompt" type="str" default="None">
  System prompt sent with every call
</ParamField>

<ParamField path="temperature" type="float" default="None">
  Sampling temperature. When `None` it is left out of the request and the provider's default applies
</ParamField>

<ParamField path="max_tokens" type="int" default="4000">
  Maximum output tokens per call
</ParamField>

<ParamField path="stream" type="bool" default="False">
  Return a generator of chunks instead of a string
</ParamField>

<ParamField path="tools_list_dictionary" type="List[dict]" default="None">
  OpenAI-format tool schemas the model may call
</ParamField>

<ParamField path="reasoning_effort" type="str" default="None">
  `"low"`, `"medium"` or `"high"` for reasoning models
</ParamField>

<ParamField path="thinking_tokens" type="int" default="None">
  Extended thinking budget for Anthropic reasoning models
</ParamField>

<ParamField path="prompt_caching" type="bool" default="False">
  Add provider-side prompt-cache breakpoints (Anthropic models). Tune with `cache_config`
</ParamField>

<ParamField path="base_url" type="str" default="None">
  Custom API endpoint, for local or self-hosted models
</ParamField>

<ParamField path="api_key" type="str" default="None">
  API key. Falls back to the provider's environment variable
</ParamField>

<ParamField path="usage_hook" type="Callable[[dict], None]" default="None">
  Called with each call's token counts. For a stream, it fires once the provider's final usage chunk has been consumed
</ParamField>

| Method or attribute | Description |
|---|---|
| `run(task=None, audio=None, img=None, imgs=None, messages=None, *args, **kwargs)` | Make one completion call. Keyword arguments override constructor settings for that call |
| `arun(...)` | Async version of `run`, with the same arguments |
| `__call__(task, *args, **kwargs)` | Same as `run(task, ...)` |
| `batched_run(tasks, batch_size=10)` | Run several prompts concurrently and return responses in input order |
| `usage` | Running totals: `input_tokens`, `output_tokens`, `cached_tokens`, `reasoning_tokens`, `total_tokens` |

### NetworkConnectionError

Raised by `LiteLLM.run()` and `arun()` when the provider cannot be reached. The message includes troubleshooting steps.

```python
from swarms import NetworkConnectionError

try:
    response = llm.run(prompt)
except NetworkConnectionError as e:
    print(f"Network error: {e}")
    # Handle retry logic
```

### LiteLLMException

Exception class for LiteLLM wrapper errors. The wrapper re-raises it if it occurs, but nothing in the framework raises it today. Provider errors such as authentication or bad-request failures reach you as LiteLLM's own exception types.

```python
from swarms import LiteLLMException

try:
    response = llm.run(prompt)
except LiteLLMException as e:
    print(f"LiteLLM error: {e}")
```

<Note>
When the call goes through an `Agent`, a model that still fails after `retry_attempts` (and after any `fallback_models`) raises `AgentLLMError` from `Agent.run()`. See [Agent error schemas](/api/schemas#agent-error-schemas).
</Note>

## Workspace Management

### WorkspaceManager

Creates a swarm's autosave directory once and writes to it on demand. The directory is `{WORKSPACE_DIR}/swarms/{ClassName}/{name}-{stamp}`, created eagerly so `dir` is usable straight after construction.

```python
from swarms import WorkspaceManager

manager = WorkspaceManager(owner=my_swarm, verbose=True)
print(manager.dir)
manager.save_conversation(my_swarm.conversation)
```

If `WORKSPACE_DIR` is unset, the manager sets it to `./agent_workspace` before creating the directory. No method raises: a failed write logs a warning and returns `None`, so autosave never fails a run.

<ParamField path="owner" type="Any" required>
  The swarm instance. Its class name and `name` attribute pick the directory, and it is the default source for conversation and config data
</ParamField>

<ParamField path="name" type="str" default="None">
  Overrides `owner.name` in the path
</ParamField>

<ParamField path="use_timestamp" type="bool" default="True">
  Timestamp in the directory name when `True`, otherwise a short UUID
</ParamField>

<ParamField path="verbose" type="bool" default="False">
  Log the directory and each successful write
</ParamField>

<ParamField path="enabled" type="bool" default="True">
  When `False` nothing is created or written and `dir` stays `None`
</ParamField>

<ParamField path="subpath" type="Optional[Sequence[str]]" default="None">
  Path segments joined onto the workspace directory in place of the default `swarms/{ClassName}/{name}-{stamp}` layout — e.g. `("agents", "my-agent-a1b2c3d4e5f6")`
</ParamField>

<ParamField path="metadata_base" type="Optional[Dict[str, Any]]" default="None">
  Base fields merged into `_autosave_metadata` on every write, in place of the default `{class_name, swarm_name, swarm_id}`
</ParamField>

| Method | Description |
|---|---|
| `WorkspaceManager.for_agent(agent, verbose=False, enabled=True)` | Class method. Build a manager over an agent's own `agents/{name}-{id}` directory |
| `save_json(filename, data)` | Write `data` as JSON into the directory |
| `save_text(filename, content)` | Write text into the directory atomically |
| `save_conversation(conversation=None, filename="conversation_history.json")` | Write conversation history. Defaults to `owner.conversation`; pass it explicitly when the swarm keeps it elsewhere |
| `save_config(additional_metadata=None)` | Write the owner's configuration to `config.json` |
| `save_state(state_data=None)` | Write a state snapshot to `state.json` |
| `save_metadata(execution_result=None, execution_metadata=None)` | Write run metadata to `metadata.json` |
| `save_all(conversation=None, execution_result=None)` | Write config, state, metadata and conversation. Returns a dict of the written paths |

Each `save_*` method returns the written path, or `None` when the manager is disabled or the write failed. `bool(manager)` is `True` only when writes will land somewhere.

<Note>
`WorkspaceManager` replaces the old `swarms.utils.swarm_autosave` module, which has been deleted. Build a `WorkspaceManager` in your swarm's `__init__` and call its `save_*` methods from `run`.
</Note>

## Example: Complete Utility Usage

```python
from swarms import (
    initialize_logger,
    create_file_in_folder,
    count_tokens,
    sanitize_file_path,
)
from swarms.utils.formatter import Formatter

# Initialize logging
logger = initialize_logger("my_app")
logger.info("Starting application")

# Create formatter for output
formatter = Formatter(md=True)

# Process some data
markdown_content = """
# Analysis Results

The quarter closed **above** forecast.
"""

# Count tokens
tokens = count_tokens(markdown_content, model="gpt-5.4")
formatter.print_panel(
    f"Report has {tokens} tokens",
    title="Token Count",
    style="bold cyan"
)

# Save to file
safe_path = sanitize_file_path("./reports/analysis_results.txt")
file_path = create_file_in_folder(
    folder_path="./reports",
    file_name="analysis_results.txt",
    content=markdown_content
)

logger.info(f"Saved to: {file_path}")

# Display markdown
formatter.print_markdown(
    markdown_content,
    title="Analysis Report",
    border_style="green"
)
```

## Best Practices

1. **Use logging extensively**: Initialize logger in all modules for debugging
2. **Sanitize paths**: Always sanitize file paths before file operations
3. **Count tokens**: Monitor token usage to stay within model limits
4. **Format output**: Use Formatter for consistent, beautiful CLI output
5. **Handle errors**: Wrap file operations in try-catch blocks
6. **Chunk large texts**: Use `Conversation.dynamic_auto_chunking()` to keep long histories inside the context window
7. **Stream responses**: Use print_streaming_panel for real-time output
