## Overview

The `swarms.tools` module provides a comprehensive toolkit for function calling, schema conversion, and tool management. It enables seamless integration with OpenAI-style function calling, MCP (Model Context Protocol) tools, and Pydantic-based schema validation.

Every name in `swarms.tools.__all__` is re-exported from the top-level package, so `from swarms import BaseTool` and `from swarms.tools import BaseTool` give you the same class.

<Note>
You rarely need these classes to give an agent tools. Pass plain functions with `Agent(tools=[...])` and the agent's [ToolManager](/api/tool-manager) builds the schemas, executes calls, and retries failures for you. For large tool sets loaded on demand, see [DynamicToolLoader](/api/dynamic-tool-loader). Use `BaseTool` directly when you need schema conversion or tool execution outside an agent.
</Note>

## BaseTool

A comprehensive tool management system for function calling, schema conversion, and execution.

```python
from swarms import BaseTool

tool_manager = BaseTool(
    verbose=True,
    tools=[my_function],
    base_models=[MyModel]
)
```

### Methods

#### func_to_dict

Convert a callable function to OpenAI function calling schema dictionary.

```python
schema = tool.func_to_dict(my_function)
```

<ParamField path="function" type="Callable" required>
  The function to convert
</ParamField>

<ResponseField name="return" type="Dict[str, Any]">
  OpenAI tool schema of the form `{"type": "function", "function": {"name", "description", "parameters"}}`
</ResponseField>

**Raises:**
- `FunctionSchemaError`: If function schema conversion fails
- `ToolValidationError`: If function validation fails

#### base_model_to_dict

Convert a Pydantic BaseModel to OpenAI function calling schema.

```python
schema = tool.base_model_to_dict(MyModel, output_str=False)
```

<ParamField path="pydantic_type" type="type[BaseModel]" required>
  The Pydantic model class to convert
</ParamField>

<ParamField path="output_str" type="bool" default="False">
  Whether to return string output format
</ParamField>

<ResponseField name="return" type="Union[dict[str, Any], str]">
  An OpenAI tool schema of the form `{"type": "function", "function": {...}}`, or with `output_str=True` the JSON string from `base_model_to_openai_function`
</ResponseField>

**Raises:**
- `ToolValidationError`: If `pydantic_type` is `None` or not a `BaseModel` subclass
- `FunctionSchemaError`: If schema conversion fails

#### multi_base_models_to_dict

Convert several Pydantic models to OpenAI tool schemas, one per model, in order.

```python
schemas = tool.multi_base_models_to_dict([Model1, Model2])
```

<ParamField path="base_models" type="List[BaseModel]" required>
  The Pydantic model classes to convert
</ParamField>

<ParamField path="output_str" type="bool" default="False">
  Return the list as one JSON string instead
</ParamField>

<ResponseField name="return" type="Union[List[Dict[str, Any]], str]">
  A list of `base_model_to_dict()` schemas, or that list JSON-encoded once when `output_str=True`
</ResponseField>

**Raises:**
- `ToolValidationError`: If `base_models` is `None`
- `FunctionSchemaError`: If any conversion fails

#### execute_function_calls_from_api_response

Detect and execute the tool calls in an OpenAI or Anthropic API response, using `function_map` or `tools`.

```python
tool = BaseTool(tools=[add])

response = {
    "choices": [{"message": {"tool_calls": [{
        "id": "call_1",
        "type": "function",
        "function": {"name": "add", "arguments": '{"a": 2, "b": 3}'},
    }]}}]
}
results = tool.execute_function_calls_from_api_response(response)
print(results)  # ["Function 'add' result:\n5"]
```

<ParamField path="api_response" type="Union[Dict[str, Any], str, List[Any]]" required>
  An OpenAI response with `tool_calls`, an Anthropic response with `tool_use` content blocks, a direct list of tool call objects (dicts or pydantic models, such as OpenAI's `ChatCompletionMessageToolCall`), a single pydantic response object, or any of these as a JSON string. Each tool in a list runs once
</ParamField>

<ParamField path="sequential" type="bool" default="False">
  Run the calls one after another instead of in a thread pool
</ParamField>

<ParamField path="max_workers" type="int" default="4">
  Thread pool size for parallel execution
</ParamField>

<ParamField path="return_as_string" type="bool" default="True">
  Format each result as `"Function '<name>' result:\n<value>"`. With `False`, return the raw values
</ParamField>

<ResponseField name="return" type="Union[List[Any], List[str]]">
  One result per tool call, in call order. `[]` when the response is `None`, is not valid JSON, or contains no tool calls
</ResponseField>

**Raises:**
- `ToolValidationError`: If neither `function_map` nor `tools` is set
- `ToolExecutionError`: If a call names an unknown function or a function raises

#### convert_funcs_into_tools

Convert all functions in the tools list into OpenAI function calling format.

```python
tool.convert_funcs_into_tools()
```

This method processes all functions in the tools list, validates them for proper documentation and type hints, and converts them to OpenAI schemas.

It also sets `function_map` from the tools list, which `execute_tool_by_name` needs.

**Raises:**
- `ToolValidationError`: If tools are not properly configured, or if any function fails conversion. A missing docstring or type hint surfaces here as a `ToolValidationError` whose message names the function

#### execute_tool_by_name

Look up a tool in `function_map` and execute it with the provided call JSON.

```python
tool.convert_funcs_into_tools()
result = tool.execute_tool_by_name(
    "add", '{"name": "add", "parameters": {"a": 1, "b": 2}}'
)
```

<ParamField path="tool_name" type="str" required>
  The name of the tool to execute. It must be a key in `function_map`
</ParamField>

<ParamField path="response" type="str" required>
  Call JSON of the form `{"name": ..., "parameters": {...}}`, `{"function": {"name": ..., "parameters": {...}}}`, or `{"functions": [...]}`. Its `name` must match `tool_name`; a bare arguments object such as `{"a": 1, "b": 2}` is skipped and returns empty results, and any other name is reported in `results` as `"Error: Function not found"`
</ParamField>

<ResponseField name="return" type="str">
  A JSON string of the form `{"results": {"add": "3"}, "summary": "add: 3"}`. Each result is converted to a string. A tool that raises is tried 3 times, then reported in `results` as `"Error after 3 attempts: ..."` rather than raised
</ResponseField>

**Raises:**
- `ToolValidationError`: If `function_map` is not set, or `tool_name` or `response` is empty
- `ToolNotFoundError`: If `tool_name` is not in `function_map`
- `ToolExecutionError`: If execution fails unexpectedly

#### Other methods

| Method | Description |
|---|---|

## Tool Registry

`swarms.tools` exports a small registry pair: the `ToolStorage` class, which holds named tool callables, and the `tool_registry` decorator, which registers a function into a `ToolStorage` instance at import time.

```python
from swarms import ToolStorage, tool_registry

storage = ToolStorage(
    name="Math Tools",
    description="Arithmetic helpers for the agent",
)

@tool_registry(storage)
def add(a: int, b: int) -> int:
    """Add two numbers together."""
    return a + b

# Look the tool back up by name and call it
add_fn = storage.get_tool("add")
print(add_fn(2, 3))  # 5
```

<Note>
There is no `tool` decorator in `swarms.tools`. To hand a plain Python function to an agent, pass it directly via `Agent(tools=[my_function])` — the framework generates the OpenAI schema from the function's type hints and docstring. Use `tool_registry` only when you also want name-based lookup through a `ToolStorage`.
</Note>

### ToolStorage

<ParamField path="name" type="str" default="None">
  Name of the registry
</ParamField>

<ParamField path="description" type="str" default="None">
  Description of the registry
</ParamField>

<ParamField path="verbose" type="bool" default="None">
  Enable detailed logging output
</ParamField>

<ParamField path="tools" type="List[Callable]" default="None">
  Initial list of tool functions
</ParamField>

#### Methods

| Method | Description |
|---|---|
| `add_tool(func)` | Add a single tool. Raises `ValueError` if a tool with the same name already exists |
| `add_many_tools(funcs)` | Add a list of tools concurrently |
| `get_tool(name)` | Return the callable registered under `name`. Raises `ValueError` if not found |
| `list_tools()` | Return the registry contents as a formatted JSON string (name, documentation, creation time per tool) |
| `set_setting(key, value)` | Store an arbitrary setting on the registry |
| `get_setting(key)` | Read a setting back. Raises `KeyError` if not set |

<Warning>
`list_tools()` returns a JSON **string** built from the registry's metadata schema, not a list of tool names.
</Warning>

  The storage instance to register the decorated function in
</ParamField>

<ResponseField name="return" type="Callable">

</ResponseField>

## Utility Functions

### get_openai_function_schema_from_func

Convert a Python function to OpenAI function calling schema. `name` and `description` are keyword-only and override the function's own name and docstring.

```python
from swarms import get_openai_function_schema_from_func

def add(a: int, b: int) -> int:
    """Add two numbers together."""
    return a + b

schema = get_openai_function_schema_from_func(
    add,
    name="add_numbers",
    description="Add two integers"
)
```

A parameter typed with a nested Pydantic model, such as `items: list[LineItem]`, produces a valid schema: the model's `$defs` are placed at the root of `parameters`, where its `$ref` points.

### base_model_to_openai_function

Convert a Pydantic BaseModel to an OpenAI function schema.

```python
from pydantic import BaseModel
from swarms import base_model_to_openai_function

class WeatherQuery(BaseModel):
    """Look up the weather for a city.

    Args:
        city: Name of the city to look up, for example
            Paris or New York.
        units: Temperature units.
    """

    city: str
    units: str = "celsius"

schema = base_model_to_openai_function(WeatherQuery)
```

<ParamField path="pydantic_type" type="type[BaseModel]" required>
  The Pydantic model class to convert
</ParamField>

<ParamField path="output_str" type="bool" default="False">
  Return a pretty-printed JSON string instead of a dict
</ParamField>

<ResponseField name="return" type="dict">
  A dict of the form `{"function_call": {"name": ...}, "functions": [{"name", "description", "parameters"}]}`
</ResponseField>

The model's docstring `Args:` section fills in each property's `description` when the field does not already set one. Indented continuation lines belong to the parameter above them, so a wrapped description such as `city` above is kept whole.

### scrape_tool_func_docs

Extract documentation from a tool function.

```python
from swarms import scrape_tool_func_docs

docs = scrape_tool_func_docs(my_function)
```

### tool_find_by_name

Find a tool by name in a list of tool objects. It compares each object's `.name` attribute and returns `None` when nothing matches, so it does not work on plain functions.

```python
from swarms import tool_find_by_name

tool = tool_find_by_name("calculator", tools_list)
```

## MCP Tools Integration

MCP integration is handled by a single class, [`MCPManager`](/api/mcp-manager). Point it at one or more servers and it manages transport, authentication, tool discovery, caching, and routing each call to the server that owns the tool.

```python
from swarms import MCPManager

manager = MCPManager(mcp_url="http://localhost:8000/mcp")

manager.list_tool_names()                                  # discover
manager.get_tools()                                        # OpenAI schemas for an LLM
manager.call_tool("get_crypto_price", {"coin_id": "btc"})  # call one directly
manager.execute_tool_calls(llm_response)                   # run what a model asked for
```

`MCPManager` and `MCPFileTokenStorage` are exported from `swarms.tools`. See the [MCPManager reference](/api/mcp-manager) for the full API, and the [MCP integration guide](/integrations/mcp) for using it from an agent.

<Warning>
**Removed in favor of `MCPManager`.** The standalone functions previously documented here — `get_mcp_tools_sync`, `aget_mcp_tools`, `execute_tool_call_simple`, `get_tools_for_multiple_mcp_servers`, and `execute_multiple_tools_on_multiple_mcp_servers` — no longer exist, along with the `swarms.tools.mcp_client_tools` module.

| Removed | Replacement |
|---|---|
| `get_mcp_tools_sync(server_path=URL)` | `MCPManager(mcp_url=URL).get_tools()` |
| `aget_mcp_tools(server_path=URL)` | `await MCPManager(mcp_url=URL).aget_tools()` |
| `get_tools_for_multiple_mcp_servers(urls=URLS)` | `MCPManager(mcp_urls=URLS).get_tools()` |
| `execute_tool_call_simple(response=R, server_path=URL)` | `await MCPManager(mcp_url=URL).aexecute_tool_calls(R)` |
| `execute_multiple_tools_on_multiple_mcp_servers(...)` | `await MCPManager(mcp_urls=URLS).aexecute_tool_calls(R)` |

Full migration notes, including the two behavioral differences, are in the [MCPManager reference](/api/mcp-manager#migration).
</Warning>


## Additional Utilities

A few other symbols are exported from `swarms.tools` for less common use cases:

- **`multi_base_model_to_openai_function`** — Convert several Pydantic `BaseModel` classes to a combined schema of the form `{"function_call": "auto", "functions": [...]}`.
- **`Function`** / **`ToolFunction`** — Pydantic models describing an OpenAI function and a tool wrapping one.
- **`load_basemodels_if_needed`** / **`get_load_param_if_needed_function`** — Coerce raw dict arguments into the Pydantic models a tool's signature declares.
- **`get_parameters`** / **`get_required_params`** — Extract the JSON-schema parameter block and the list of required parameter names from a callable.
- **`ToolStorage`** / **`tool_registry`** — Register and look up tools by name; see [Tool Registry](#tool-registry) above.
- **`MCPManager`** / **`MCPFileTokenStorage`** — MCP transport, auth, discovery, and routing; see the [MCPManager reference](/api/mcp-manager).

## Exceptions

`BaseTool` raises the exceptions below. They are defined in `swarms.tools.base_tool` and are **not** re-exported from `swarms.tools` or `swarms`, so import them from the module directly:

```python
from swarms.tools.base_tool import (
    BaseToolError,
    ToolValidationError,
    ToolExecutionError,
    ToolNotFoundError,
    FunctionSchemaError,
    ToolDocumentationError,
    ToolTypeHintError,
)
```

All of them subclass `BaseToolError`.

<Note>
These are `BaseTool`'s own errors. Inside an agent, a tool call that still fails after `tool_retry_attempts` raises `AgentToolExecutionError`, which the agent catches and writes into the conversation so the model can react. It does not escape `Agent.run()`. That class and the other agent errors live in `swarms.schemas`; see [Agent error schemas](/api/schemas#agent-error-schemas).
</Note>

### BaseToolError

Base exception class for all BaseTool related errors.

### ToolValidationError

Raised when tool validation fails.

### ToolExecutionError

Raised when tool execution fails.

### ToolNotFoundError

Raised when a requested tool is not found.

### FunctionSchemaError

Raised when function schema conversion fails.

### ToolDocumentationError

Raised when tool documentation is missing or invalid.

### ToolTypeHintError

Raised when tool type hints are missing or invalid.

## Best Practices

1. **Always add type hints**: Functions must have type hints for reliable schema generation
2. **Include docstrings**: Comprehensive docstrings improve tool descriptions
3. **Validate inputs**: Use Pydantic models for complex input validation
4. **Handle errors**: Wrap tool execution in try-catch blocks
5. **Enable verbose mode**: During development, enable verbose logging to debug issues

## Example: Complete Tool Setup

```python
from pydantic import BaseModel
from swarms import BaseTool

# Define a Pydantic model
class MathInput(BaseModel):
    a: int
    b: int
    operation: str

# Define a function with type hints and docstring
def calculate(a: int, b: int, operation: str) -> int:
    """Perform arithmetic operations on two numbers.
    
    Args:
        a: First number
        b: Second number
        operation: Operation to perform (add, subtract, multiply, divide)
    
    Returns:
        Result of the operation
    """
    if operation == "add":
        return a + b
    elif operation == "subtract":
        return a - b
    elif operation == "multiply":
        return a * b
    elif operation == "divide":
        return a // b
    else:
        raise ValueError(f"Unknown operation: {operation}")

# Create tool manager
tool_manager = BaseTool(
    verbose=True,
    tools=[calculate],
    base_models=[MathInput]
)

# Convert tools to OpenAI schema
tool_manager.convert_funcs_into_tools()

# Execute a tool
result = tool_manager.execute_tool_by_name(
    "calculate",
    '{"name": "calculate", "parameters": {"a": 10, "b": 5, "operation": "multiply"}}',
)
print(result)  # {"results": {"calculate": "50"}, "summary": "calculate: 50"}
```
